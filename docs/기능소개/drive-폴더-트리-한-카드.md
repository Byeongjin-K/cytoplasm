# Drive 폴더 트리 — 작업 한 건을 카드 한 장·승인 한 번으로

## 무엇을

`drive-save --manifest <staged json> --folder <부모 폴더 id>` 가 하위 폴더가 여러 개인 파일 묶음(수십~수백 개)을 한 작업으로 받는다. 카드 한 장에 부모 폴더, 만들 폴더, 파일 수·총 크기가 실리고, 전체 목록(경로·크기·sha256)은 카드 바로 아래 글로 붙는다. 형이 ✅ 를 한 번 누르면 워처가 폴더를 위에서부터 만들고 목록의 파일을 모두 올린다.

## 왜

2026-11-23: 유돌이 공돌 측량 자료(76파일, 하위 폴더 여러 개)를 이 PC 도리 관문(3129)으로 파일·폴더마다 따로 올리다가 근거 글 쓰기 한도를 넘었다. 그 뒤로 쓰기마다 승인 카드가 생겨 #yoodori 에 약 40장(재시도 중복 포함)이 쏟아졌고 21개만 올라갔으며, 폴더 생성이 승인을 기다리는 동안 그 아래 파일은 404 로 실패했다. 기존 `drive-save` 는 파일 20개·폴더 구조 없음·게이트 인자 64개 제한이라 이 묶음을 받을 수 없었다. 형 지시: "드라이브 업로드 하는거, 건별로 파일들 묶어서 승인 받도록 설정해줘."

## 사용 시나리오

**측량 자료 폴더째 올리기.** 형: "공돌이 준 측량 자료 드라이브 측량자료 폴더에 올려 줘."

1. 유돌: 파일마다 `stage <이름>` 으로 노드 staging 에 올린다(파일당 64 MiB 까지).
2. 유돌: 매니페스트를 만들어 `stage survey-manifest.json` 으로 올린다.
   ```json
   {"version": 1, "files": [
     {"path": "현장측량/1일차/scan-001.las", "staged": "survey-001.las", "sha256": "<64자>", "size": 123456}
   ]}
   ```
   `path` 는 부모 폴더 아래 경로, `staged` 는 같은 staging 의 파일 이름(경로 금지, 확장자는 `path` 와 같게), `path` 의 이름은 `-` 로 시작하거나 확장자 앞에 앞뒤 공백이 있으면 안 된다(따로 받는 덮어쓰기 카드에서 이름이 그대로 남도록), `sha256`·`size` 는 올린 바이트.
3. 유돌: `drive-save --manifest survey-manifest.json --folder <부모 폴더 id> --summary '측량 자료'`(끝에 형 글 좌표).
4. 카드(판본 `effect-request-v3`): `저장 폴더: 측량자료 (경로 …, id …) 아래`, `폴더 6개(새로 만들 폴더 6개 …)`와 폴더별 파일 수, `파일 76개(합계 …) — 이 목록 전체(경로·크기·sha256)가 승인 해시에 묶인다`, `전체 목록: 이 카드 아래 글 3개`. 형은 목록을 훑고 ✅ 한 번.
5. 워처(2분)가 부모 폴더가 형만 볼 수 있는지 다시 확인하고, 폴더를 위에서부터 만들고(만든 폴더도 비공개 확인), 파일마다 새로 올려 다시 내려받아 sha256 을 확인한다. 스레드에 `✅ Drive 폴더 저장 완료(비공개) … 파일 76개, 폴더 6개` 와 폴더 링크가 남는다.

**이어 올리기.** 일부가 이미 같은 내용으로 올라가 있으면(예: 사고 때 올라간 21개) 카드에 `이미 같은 내용으로 있어 건너뛰는 파일 21개` 로 보이고 나머지만 올린다.

**같은 요청을 다시 보내면.** 형 글·부모 폴더·목록이 같으면 같은 작업이다. 카드가 기다리는 중이면 그 카드를 다시 가리키고(새 카드 없음, 요약 문구가 달라도), 이미 저장됐으면 `EFFECT-REQUEST-ALREADY … status=done`, 형이 ⛔ 한 작업이면 다시 묻지 않는다(exit 4). 목록이 바뀌면 다른 작업이라 새 카드다.

**일부만 실패하면.** 나머지는 올리고 파일별 결과를 남기며, 다음 틱이 같은 승인으로 실패한 파일만 다시 올린다(최대 5번). 끝내 실패하면 `❌ 일부만 저장됨 … 76개 중 74개` 와 실패한 파일 목록.

**거절·따로 승인되는 경우.**
- 같은 이름의 다른 파일이 이미 있으면 덮어쓰지 않는다. 요청 때 보이면 카드에서 빼고 `DRIVE-SAVE-OVERWRITE-NEEDS-CARD path=… folder=<폴더 id>` 줄을 내므로, 같은 줄에 찍힌 `request: drive-save --card --folder <그 폴더 id> --file <staged> --title <트리 이름>` 에 `--summary <설명>` 과 형 글 좌표(`--origin-channel-id …` `--origin-message-id …`)를 붙여 따로 카드를 받는다(`--card` 는 노드의 카드 없는 저장 스위치가 켜져 있어도 카드를 올리고, `--title` 이 트리에서의 이름을 지킨다. 관문이 받지 않는 문자(`& ; | $` 따옴표 등)가 이름에 있으면 `--title-b64` 로 찍힌다). 모든 파일이 덮어쓰기면 카드 없이 거절하면서 파일마다 같은 요청을 알려 준다. 카드 뒤에 생긴 같은 이름 파일은 그 파일만 실패로 남긴다.
- 목록 밖 파일은 올리지 않는다(동결 폴더에 나중에 생긴 파일 포함). 매니페스트의 `staged` 에 경로(`/`, `..`)를 쓰거나 `path` 에 `..`·빈 이름·`.` 으로 시작하는 이름, 같은 경로 두 번, 파일과 폴더 이름 겹침은 거절한다.
- 선언한 sha256·크기와 실제 바이트가 다르면 아무것도 저장하지 않고 카드도 올리지 않는다.
- 파일 501개 이상, 폴더 8단보다 깊은 경로, 목록 글이 40개를 넘는 목록(아주 긴 경로가 많을 때), 다른 사람과 공유된 부모 폴더는 거절한다(카드 없음, 나눠서 요청).
- 카드 없는 저장(`save-now`, 노드 「Drive 저장 자동 쓰기」 스위치)은 폴더 트리에 쓰지 않는다. 트리는 늘 카드 한 장이다.
- 카드 아래 목록 글을 올리지 못하면 카드도 지운다(목록 없이 승인받지 않는다). 승인 전에 목록 글이 지워지면 그 카드는 사라진 것으로 보고 실행하지 않으며, 바뀐 목록 글은 우리 카드로 보지 않는다.
- 같은 요청이 동시에 두 번 와도 요청 id 가 키에서 정해져 먼저 저장된 하나만 남는다(카드 한 장).
