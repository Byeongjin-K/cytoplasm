# 정기 작업 실패 알림은 한 번만, 사람 말로

## 무엇을

정기 작업(사용자 타이머 러너)의 실패·경고 알림은 같은 작업의 같은 종류 고장이면 처음 한 번만 올린다.
고장이 이어지면 6시간마다 한 번 다시 알리고, 회복하면 「다시 정상」 한 줄을 올린다.
글은 사람 말 두 줄(무슨 작업이 왜 안 되는지, 다음 실행에서 다시 시도하고 유돌이 살펴본다는 것)이고
종료코드·`key=value`·표식 코드는 싣지 않는다. 원문은 작업 출력 기록과 journal 에 남는다.

## 왜

2026-10-21 형 질문: "이런 코드 경고 개선한거 아니었어?이 에러는 안고쳐져?". 같은 날 메일 동기화 작업이
15분마다 실패하며 2시간 넘게 같은 코드 글(종료코드·`error_code`·`failure_signature`)을 10번 넘게 페어 채널에 쌓았다.
앞선 지시(2026-10-18 21:43 KST)는 경고 코드를 형에게 바로 보이지 말라는 것이었다. 실패 원인 자체는 별도 수정이다.

## 사용 시나리오

- 메일 동기화가 시간 초과로 실패 → 페어 채널에 「⚠️ 정기 작업 'mail-sync-watch'가 실패했어요: 시간 안에 끝나지
  않았어요.」와 안내 한 줄. 15분 뒤 같은 실패는 글 없이 journal 에 보류 표식만 남는다.
- 중간에 다른 원인(예: 메일 서비스 연결 실패)으로 바뀌면 그 원인으로 새 글 한 번.
- 6시간 넘게 이어지면 「아직 실패 중이에요(N시간째, M번 연속)」 한 번.
- 다음 실행이 성공하면 「✅ 정기 작업 'mail-sync-watch'가 다시 정상이에요(실패 M번, N시간 만에).」
- 실패 경로: 알림 전송이 실패하면 "보냈음"으로 적지 않아 다음 실행이 다시 보낸다(기존처럼 그 실행은 실패로 센다).
- 페어 채널이 없는 설치는 실패 알림만 같은 규칙으로 홈 채널에 가고, 경고 줄은 지금처럼 본문과 함께 간다.

## 관련

- 발신·판정: `automation/cron_timer_run.py`(`deliver`·`trouble`·`alert_text`, 간격 `REALERT`), 알림 상태
  `~/.hermes/cron-timers/alerts/<작업>.json`(0600). 받는 곳은 [고장 알림 페어 채널](고장-알림-페어-채널.md) 규칙 그대로.
- 코드 줄 판정: `automation/interop/owner_text.py`. doctor 의 연속 실패 판정(`cron-timers/<작업>.json`)은 바뀌지 않는다.
- 시험: `tests/unit/test_cron_timer.py`, `tests/unit/test_owner_text.py`. 승인 게이트는 관여하지 않는다.
