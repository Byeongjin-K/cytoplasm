# 세션 탭에 여러 도리

**무엇을**: 프로젝트 대시보드 「세션」 탭이 작업 컴퓨터 하나의 세션만이 아니라, 다른 컴퓨터의 다른 계정에서 도는
도리(옥돌·무돌·유돌 등)의 레인·코딩 세션·작업 창·서비스까지 한 화면에 합쳐 보여 준다.

**왜**: 2026-10-19 옥돌·무돌·유돌이 다른 컴퓨터의 각 계정으로 옮겨 갔다. 세션 집계(`session_feed/feed.sh`)는 작업 컴퓨터의
레인 폴더만 읽게 되어 있었고, 옮겨 간 옥돌의 레인 폴더가 사라지자 10분마다 도는 집계가 `ENOENT` 로 실패해 세션 탭이 멈췄다.

**어떻게**: 작업 컴퓨터의 비공개 env 에 두 줄을 더한다.

```
SESSION_FEED_PEERS="okdori moodori yoodori"
SESSION_FEED_PEER_RUN=<그 계정으로 명령 하나를 돌리는 래퍼>   # 호출 모양: <래퍼> <계정> bash -c <스크립트> <기준 시각>
```

`feed.sh` 는 자기 컴퓨터의 집계를 만든 뒤, 계정마다 같은 `collect.mjs` 를 표준 입력으로 보내 그 계정에서 같은 기준 시각
(`SB_NOW`)으로 돌리고 결과 행을 합쳐 보낸다. 각 계정의 입력(레인 폴더·분류 규칙·서비스 표)은 그 계정의
`~/.config/session-feed/feed.env` 에 있다. 보내는 것은 지금처럼 메타데이터뿐이다(레인 키·제목·대화·경로 없음).

## 사용 시나리오

- **평소**: 10분마다 집계가 돌고 저널에 `SESSION-FEED sent … bytes from 4 collector(s)` 가 남는다. 세션 탭의 서비스
  묶음에 「짱돌 메신저 수신」·「옥돌 메신저 수신」·「무돌 메신저 수신」·「유돌 메신저 수신」이 함께 보이고, 리드 작업 창도
  넷이 센다.
- **한 계정이 실패할 때**(그 컴퓨터가 꺼짐 등): 나머지 계정의 집계는 그대로 보내고 저널에
  `SESSION-FEED missing peer(s): <계정>` 을 남긴 뒤 종료 코드 3 으로 끝난다. 탭의 「세션 집계 전송」 행이 「실패」로 보인다.
- **도리가 또 옮겨 갈 때**: 집계를 보내는 쪽이 다른 컴퓨터로 가도 `SESSION_FEED_PEER_RUN` 만 그 컴퓨터에서 계정을 바꾸는
  명령(예: `sudo -n -u`)으로 바꾸면 된다. 대시보드 코드는 바뀌지 않는다.
