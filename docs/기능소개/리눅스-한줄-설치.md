# 리눅스 한 줄 설치와 처음 설치 막힘 고침

## 무엇을

리눅스에서도 윈도우처럼 터미널에 한 줄만 붙이면 사이토플라즘과 도리가 깔린다. 같은 줄로 업데이트한다.
리눅스·윈도우 모두 도리 리드가 쓰는 omo 와 봇 설정 파일(`~/.dori/dori.env`)까지 준비하고, 리눅스는 디스코드 수신
같은 도리 상시 루프를 사용자 유닛 `dori-serve.service` 로 켠다.

## 왜

깨끗한 우분투 24.04 와 윈도우에서 README 만 보고 처음 깔아 보니(2026-11-15) 이랬다.

- 리눅스: README 첫 명령이 체크아웃 없이 `No module named 'automation'` 으로 실패했고, git·bun·omo 를 어디서 어떻게
  까는지 알려 주지 않았다. 손 단계 13번에 바깥 검색이 4번 필요했다. 끝까지 가도 디스코드 수신 루프가 뜨지 않아
  첫 메시지에 답할 수 없었다.
- 윈도우: 파이썬 런처(`py`)가 없는 PC에서 한 줄이 `The term 'C' is not recognized` 로 멈췄다. 파이썬을 찾은 결과가
  배열에서 문자열로 풀려 첫 글자 `C` 를 실행했기 때문이다. 파이썬이 있으면 68초에 깔렸지만 omo 가 없어 리드가
  안 켜졌고 `dori.env` 도 없었다.

## 사용 시나리오

**정상 경로.** 동료 연구자가 리눅스 터미널에 붙여 넣는다.

```bash
curl -fsSL https://raw.githubusercontent.com/orientpine/cytoplasm/main/install.sh | bash
```

git 이 없으면 `sudo` 비밀번호를 한 번 묻고 깐다. bun·omo 는 각자의 설치기로 계정에 깔린다. 릴리스 서명을 확인한
뒤 도리가 설치되고, 리드 탭에 omo 입력창이 뜨고 `dori-serve.service` 가 켜진다. 남은 일은 셋뿐이다.
`~/.dori/dori.env` 네 줄(봇 토큰·서버·채널·소유자 id)을 채우고, 리드 탭에서 `/login`, 그리고 "Dori mode".

**거부 경로.**

- 받은 `update-trust.pub` 지문이 README 값과 다르면 `CYTO-LINUX-FINGERPRINT-MISMATCH` 로 클론에서 아무것도 실행하지 않는다.
- 서명 없는 더 새 태그는 `CYTO-UNSIGNED-SKIP` 으로 건너뛰고 마지막 서명 릴리스를 깐다.
- 이미 루프를 유닛 하나씩(`dori-inbound.service` 등)으로 돌리는 계정에는 `dori-serve.service` 를 만들지 않는다
  (`DORI-SERVE-UNIT-SKIP`, 같은 디스코드 글에 두 번 답하지 않게).
- 봇 토큰을 넣기 전에는 수신 루프가 `DISCORD_LISTENER_FATAL close=4004` 를 남기고 늘어나는 간격으로 다시 시도한다.

## 관련

- `install.sh`·`install.ps1`(저장소 루트), `automation/install/dori.py`(`dori-env`, bun 찾기, 빠진 도구 안내),
  `automation/install/dori_herdr.py`(`serve_unit`, omo 안내), `automation/install/update.py`
- 시험: `tests/unit/test_install_sh.py`, `tests/unit/test_install_dori_herdr.py`, CI `windows-install`
- 승인 게이트는 관여하지 않는다(설치 경로). 안내: [설치 가이드 「도리 기본 설치」](../guide/install.md#도리-기본-설치-p6)
