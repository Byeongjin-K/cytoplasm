# 유돌이 이름으로 기관메일 주소를 찾는다

## 무엇을

유돌 게이트에 읽기 명령 `mail-resolve <이름>` 하나를 더했다. 노드 `agent` 가 기관 웹메일 메일쓰기 화면의
받는사람 자동완성(조직도·개인 주소록·수발신 이력)으로 그 이름의 주소 후보를 찾아 돌려준다. 아무것도
보내거나 저장하지 않는다.

## 왜

예전에는 에이전트가 같은 계정 안에서 `mail_wrapper.py resolve --name` 을 바로 불러 신청자 이름만으로 주소를
찾았다. 유돌이 별도 계정으로 옮긴 뒤에는 강제명령 게이트로만 노드에 닿는데, 그 게이트에 이 조회가 없어
주소 칸이 없는 신청서 행에 안내 메일을 보낼 수 없었다(2026-10-21, 형 Q344 「더하기」).
같은 날 조회 자체도 느린 웹메일 페이지에서 매번 실패하던 결함을 고쳤다
([페이지 load 보정](기관메일-페이지-load-보정과-발송-실패-안내.md)).

## 사용 시나리오

- **주소가 하나**: 형 "새 신청자 두 명에게도 안내 메일 보내" → 유돌이 이름마다 `mail-resolve <이름>` →
  `ambiguous=false` 면 그 주소로 `mail-compose` 카드를 올린다 → 형은 카드에서 받는 사람을 보고 ✅ 만 누른다.
- **동명이인·여러 주소**: `ambiguous=true` → 유돌이 정렬된 후보(조직도 먼저)를 형에게 보여 주고 고르게 한다.
  자동으로 고르지 않는다.
- **못 찾음**: 후보 0건 → 주소를 지어내지 않고 형에게 못 찾았다고 말한다.
- **거부**: 이름이 없거나, 두 낱말 이상이 따로 오거나, `-` 로 시작하거나, 40자를 넘거나, 셸 메타문자가
  있으면 `YOODORI-GATE-REFUSED` 로 끝나고 웹메일에 닿지 않는다.

## 관련

- 게이트 `automation/yoodori_gate/yoodori_read_gate.py`(`build` 의 `mail-resolve`), 시험
  `tests/unit/test_yoodori_gate_mail_resolve.py`. 게이트 로그는 명령명·rc·초만 남기고 이름은 남기지 않는다.
- 조회 본체와 후보 판정 규칙: `skills/mail/SKILL.md` 「수신자 이름→이메일 해석 (resolve)」.
- 승인: 조회는 읽기라 카드가 없다. 발송은 기존 메일 카드의 형 ✅ 로만 나간다. SSH 키·방화벽·sudoers·
  OAuth 범위는 그대로이고 게이트 파일만 다음 릴리스로 바뀐다.
