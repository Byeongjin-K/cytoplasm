# 기관메일 로그인 페이지가 늦게 열리면 그 자리에서 다시 연다

## 무엇을

기관메일 수집(`mail-sync-watch`)이 로그인 페이지를 여는 단계에서 시간 초과가 나면, 그 실행을 실패로
끝내지 않고 같은 자리에서 페이지를 다시 연다(최대 3번, 5초 간격). 페이지는 열렸는데 로그인 칸이 끝내
나타나지 않을 때도 한 번 더 연다. 아이디·비밀번호를 넣기 전 단계라 다시 열어도 아무것도 두 번 보내지 않는다.

## 왜

2026-10-24 19:31 KST 형 지적: 같은 정기 작업 실패 알림이 계속 뜨는데 원인이 안 고쳐진 것 같다. 수집 실패 기록을
모아 보니 원인은 매번 이름만 달랐을 뿐 같은 자리였다 — 메일 사이트가 늦게 떠서 로그인 페이지 열기에서 멈췄다.

- 10-24 19:30 KST: 페이지 열기가 「CDP command timed out: Page.enable」로 멈춤(한 번, 다음 실행은 정상).
- 10-21 15:41 KST: 페이지는 열렸는데 로그인 칸이 90초 안에 안 나타남.
- 10-02 16:01 KST: 페이지 열기가 「Operation timed out」인데 아직 로그인 주소에 닿지 않음.
- 같은 주 로그인 페이지 열기 475번 중 83번이 25초를 넘었다(중앙값 4초, 상위 10% 27초, 최대 87초).

전에는 「Operation timed out」이면서 이미 로그인 주소에 닿은 경우 하나만 견뎠고, 나머지는 10분 뒤 다음 실행이
유일한 재시도였다. 그래서 사이트가 한 번 늦을 때마다 실패 알림이 한 번씩 났다.

10-21 오전의 2시간 넘는 연속 실패(15분 제한 초과)는 다른 원인(큰 첨부 내려받기)이었고 같은 날 고쳐져 그 뒤로 다시 나지 않았다.

## 사용 시나리오

- 사이트가 늦게 떠 첫 열기가 시간 초과 → 5초 뒤 다시 열어 로그인하고 수집을 끝낸다. 형 채널에는 아무 글도 없다.
- 페이지는 떴는데 로그인 칸이 안 나옴 → 한 번 더 열고 칸이 나오면 로그인한다.
- 세 번 다 시간 초과이거나, 주소를 못 찾는 등 다른 오류 → 지금처럼 그 실행은 실패로 끝나고 다음 실행이 다시 시도한다.

## 관련

- 시험: `tests/unit/test_mailon_login_open_timeout.py`, `tests/unit/test_mailon_login_slow_page.py`.
- 알림 경로·승인 게이트는 바뀌지 않는다([정기 작업 실패 알림은 한 번만](정기-작업-실패-알림-한-번만.md)).
