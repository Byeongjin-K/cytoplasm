# 고장 알림은 유돌·짱도리 페어 채널로

## 무엇을

정기 작업 실패, 헬스체크·doctor 고장, 첨부 다운로드 재시도 소진은
소유자 채널 대신 페어 채널에 유돌 봇으로 보낸다. 유돌은 재시도·다음 틱을 먼저
확인하고, 해결하지 못하면 원인과 시도 내역을 붙여 짱도리에게 요청한다.
로그인·결제처럼 소유자 본인 결정이 필요한 요청은 기존 소유자 경로를 쓴다.
이 변경은 고장 통지의 목적지를 정하며 자동 수리 권한을 새로 부여하지 않는다.

## 왜

소유자 지시(2026-10-18 21:43 KST):
> 저런 경고 코드를 바로 나에게 보여주지 말고, 자체 해결하던가, 그러고 안되면 짱도리에게 해결 요청하던가 해.

같은 날 앞선 지시는 “문제알림을 유도리가 받고 짱도리에게 말하기”였다.
첨부 다운로드가 아직 재시도 중인데 매 틱을 실패로 세어 경고를 보내던 것도 바로잡았다.

## 설정과 사용 시나리오

- 릴리스 호스트의 `~/.hermes/release-flags/fault-channel`에 설치별 페어 채널 ID만
  넣는다(17~20자리 숫자, 개행 없음). 기존 `notice-bot=yoodori` 전환이 전제다.
  릴리스 카드는 “고장 알림은 #dori-pair 로(유돌 먼저)” 한 줄을 표시하고
  `fault-channel:<id>` 표면과 SHA-256으로 목적지를 승인 해시에 묶는다.
- 소유자 릴리스 승인 뒤 기존 notice-bot 배포가 agent·peer 홈과 ops 비공개 루트의
  `notice-bot.json`에 선택 필드 `fault_channel_id`를 함께 쓴다(0600).
  세 계정의 읽기 검증과 영수증도 목적지를 대조한다. 별도 파일·토큰은 없다.
- 예: 정기 작업 업로드 실패 → 유돌 봇이 페어 채널에
  `정기 작업 'mail-attachment-drive-watch' 실패(종료코드 1)`와 진단을 보낸다.
  소유자 채널에 경고 코드를 복사하지 않는다.
- 첨부 복구는 수신일(없으면 `first_seen`)이 최근 14일이며 MailOn 자체 시도 횟수가
  5회 미만인 항목만 시도한다. 오래됐거나 이미 소진한 항목은 조회만 하고 넘긴다.
  진행 중인 재시도는 종료코드 0·빈 stdout이다. 별도 복구 예산 5회를 소진한 항목은
  틱당 통지 한 건(전체 건수·첨부명 최대 3개)으로 묶는다.
  통지 실패 시 다음 틱에 재전송하고, 실제 업로드·검증 실패는 여전히 종료코드 1이다.
- 플래그 삭제 후 재배포하면 고장 목적지만 기존 통지 경로로 복원된다.
  미설정 설치는 기존 경로를 그대로 쓰며 통지를 버리지 않는다. 회복만 있는 틱은 침묵한다.

## 페어 채널 글은 사람 말 한 줄로 (2026-10-20 Q304)

형이 #dori-pair 의 유돌 글(`대상:`·`사실:`·`위치:`·`인계:`·`되돌리기:` 칸, `**✅ 헬스체크 관측**` 머리)을 보고
"이렇게 출력되는 거 없앤 거 아니었어?" 라고 물었다. 알림은 남기고 모양만 바꾼다.

- 페어 채널로 가는 통지(`notify_owner(..., fault=True)` 와 진단 줄 때문에 페어로 옮겨진 통지)는
  `owner_message.render_report` 로 머리·칸·참조 줄 없이 한 줄이 된다: 무엇이 됐나, 확인할 곳 하나, 남은 일.
- 예: `헬스체크 「node release fully deployed」 점검이 새로 실패했습니다. 남은 일은 원인 확인; 확인 전 재시작·설정변경·키 재발급 금지.`
- 형 채널 판본(`owner-ko-v1`~`v5`)의 바이트와 저장된 봉투는 그대로다. 봉투 없는 문자열 통지와
  정기 작업 실패 글(`cron_timer_run`)은 이 판정 밖이다.
- 강제: `tests/unit/test_pair_report_shape.py`.

**2026-10-19 Q281**: 헬스체크는 같은 검사가 10분 넘게(5분 스윕으로 세 번째) 계속 실패할 때만 #dori-pair 에 한 번 올린다. 한 번 깜빡인 실패는 올리지 않고, 회복은 알리지 않는다(`healthcheck_notify.SUSTAIN_SECONDS`, 상태 파일 `first_seen`).
