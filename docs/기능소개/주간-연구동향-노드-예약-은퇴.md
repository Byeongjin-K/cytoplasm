# 주간 연구 동향 — 노드 예약 은퇴

## 무엇을

주간 연구 보고서 생성·발송과 키워드 관리는 cytoplasm 밖 별도 연구 에이전트
공도리가 맡는다. 보고서 요청과 키워드 추가·확인·삭제는 공도리 채널에서 한다.
유돌은 노드 `topics` 등록을 주간 보고서에 반영한다고 안내하지 않는다.

## 왜

같은 주에 노드와 별도 연구 에이전트가 보고서를 각각 보내는 중복을 막는다.
노드의 `research-trends` 예약 선언과 배포기의 등록을 없애고, 다음 승인된
릴리스가 기존 `autophagy-cron-research-trends.timer`와 대응 서비스를 제거한다.
노드에서 타이머를 손으로 끌 필요는 없다.

## 사용 시나리오

1. 소유자가 공도리 채널에서 이번 주 보고서나 추적 키워드 변경을 요청한다.
2. 주간 보고서와 키워드는 공도리가 관리한다. 노드의 기존 주제 목록을 바꾸어도
   공도리의 목록에 자동으로 반영되지 않는다.
3. 이 변경이 포함된 릴리스를 소유자가 승인하면 배포기가 실행 중인 노드 타이머를
   정지·비활성화하고, 서비스 정지를 확인한 뒤 생성 유닛 파일을 지운다.
4. 배포기는 유닛 부재와 정지 상태를 다시 확인한다. 노드 보고 예약은 재생성되지 않는다.

유닛 상태를 읽을 수 없거나 정지가 확인되지 않으면 삭제·완료 판정을 거부한다.
이는 PR만으로 노드 반영이 끝났다는 뜻은 아니며, 실제 정리는 다음 릴리스에서 수행한다.

## 보존과 관련 경로

- `automation/retired_jobs/deploy-manifest.txt`의 필수 `retired-job-v1` derived 선언이
  실제 제거를 맡는다. `policy=retired`는 잔여물 관측만 하므로 사용하지 않는다.
- `automation/research_trends/deploy.sh`는 스크립트·런타임·프롬프트만 보존하고
  Hermes cron이나 systemd 타이머를 등록하지 않는다.
- 기존 보고서·주제 데이터는 지우거나 외부 에이전트로 자동 이관하지 않는다.
  남은 코드와 `topics` 결합 정리는 [후속 과제](../follow-ups.md)에 기록한다.
- `skills/topics/SKILL.md`, `skills/report/SKILL.md`,
  `dori/roles/yoodori/AGENTS.md.tmpl`도 같은 업무 소유권을 안내한다.
