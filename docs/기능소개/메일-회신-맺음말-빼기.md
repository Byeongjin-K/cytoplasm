# 메일 회신 초안 맺음말 빼기

노드 운영자가 메일 자동 회신 초안의 맺음말(`감사합니다.` + `<owner-name> 올림`)을
뺄 수 있다. 끄면 초안은 상대에게 다음 행동을 청하는 마지막 문장에서 끝나고,
맺음말과 이름은 발송 계정의 기본 서명이 붙인다. 기본값은 지금과 같다.

## 왜

회신 프롬프트 v2의 문체 가이드가 맺음을 `감사합니다.` → `<owner-name> 올림`으로
고정한다. 기관메일 계정 서명에 같은 맺음말이 이미 들어 있는 소유자는 발송본에
맺음말이 두 번 들어가므로, 초안마다 손으로 지워야 했다.

## 켜고 끄기

릴리스 호스트의 운영자 계정에서 줄바꿈 없이 `omit`만 쓴다. 다른 값·공백·빈 파일은 거부한다.

```bash
mkdir -p ~/.hermes/release-flags
printf %s omit > ~/.hermes/release-flags/mail-reply-closing
chmod 600 ~/.hermes/release-flags/mail-reply-closing
```

기존 [릴리스 절차](../guide/manual-maintainer.md)를 따른다. 릴리스 카드에
`메일 회신 초안 맺음말(감사합니다·이름 올림) 빼기 — 계정 서명이 맺음을 붙임`이
표시되고 `mail-reply-closing:omit` 표면과 HEAD가 승인에 묶인다. 승인 뒤 선언된
`push_file`이 노드 `~/.hermes/mail-reply-closing.mode`(0600)에 `omit`을 쓰고
다시 읽어 확인한다. 다른 HEAD의 승인으로는 켤 수 없다.

파일을 지우고 다음 승인 릴리스를 하면 `keep`이 배포되어 예전 맺음말로 돌아간다.
표식이 없거나 `keep`이면 프롬프트와 초안 본문은 바이트 그대로다. 표식이 깨졌거나
읽히지 않으면 초안을 만들지 않는다(exit 3).

## 사용 시나리오

다이제스트에서 ✍️ 를 누르거나 "3번 메일, 참석 가능하다고 회신해줘"라고 지시한다 →
`omit`이면 모델에 맺음말 없이 끝내고 서명은 계정이 붙인다는 규칙이 간다 → 모델이
그래도 끝에 `감사합니다.`나 `<이름> 올림|드림` 줄을 쓰면 그 끝줄만 지운다(본문 안의
`감사합니다`는 그대로) → 승인 카드에는 맺음말 없는 회신문이 보이고 ✅ 뒤 계정 서명과
함께 발송된다.

`mail-compose`로 쓰는 새 메일(예: 출장 안내 표준)은 에이전트가 직접 쓰므로
`skills/mail/SKILL.md`의 같은 표식 규칙을 따른다.

## 관련

- `automation/mail_reply_closing.py`와 같은 이름의 배포 패키지
- `skills/mail/scripts/triage_llm.py::draft_reply`, `mail_reply_format.py`
- `release_approval.py`, `release_spec_message.py`, `deploy_all_observe.py`, `deploy_all.sh`, `release.sh`
- 프롬프트 파일(`reply-draft-v1.md`·`v2.md`)은 고치지 않는다. 알려진 맺음 규칙 줄만 실행 때 바꾸고,
  그 줄이 없는 프롬프트에서 `omit`이면 초안을 거부한다.
