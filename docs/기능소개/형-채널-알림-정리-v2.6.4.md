# 형 채널에는 형이 볼 것만 — 리마인더 한 줄, 운영 경고는 짝 채널로

## 무엇을
형 채널(유돌 채널)로 가던 노드 알림을 정리했다. 일정·마일스톤 리마인더는 한 줄로 오고, 같은 회의를 두 번 알리던 노드 일정 리마인더는 꺼졌다. 운영 경고는 형 채널 대신 짱돌·유돌이 보는 짝 채널(`#dori-pair`)로 간다. 주간 회귀 은행은 은퇴한 Hermes 경로 때문에 빨간불이 되지 않고, 노드 agent 의 실제 홈에 시험 흔적을 남기지 않는다.

## 왜
- 2026-10-19 12:25 KST 형 채널에 `대상: 리마인더 (<일정 id>|…) 사실: ⏰ …` 다섯 줄 원형이 그대로 보였다.
- 같은 13:30 회의를 유돌(35분 전)과 노드(한 시간 전)가 두 번 알렸다. 형 결정 Q276: "유돌 것만 남기고 노드 일정 리마인더는 끄기 — 마일스톤 D-day 알림은 노드 그대로".
- 수렴 점검·신뢰 키·릴리스 백로그·승인 회수·관리형 스킬 도착·감사·meeting 갱신 알림이 형 채널로 왔다. 형 지침 faults-to-pair: 경고는 유돌이 해결하고 안 되면 짱돌에게.
- v2.6.2 가 report-hub·peer·Hermes 메모리를 은퇴시킨 뒤 주간 은행(이 PC crontab, 월 12:15 KST)이 그 세 시나리오에서 실패해 수리 패치 적용이 막혔고, personal-memory 드라이버가 노드 agent `~/.hermes` 에 빈 `kanban.db` 를 다시 만들었다.

## 바뀐 것
- 소유자 메시지 판본 `owner-ko-v5`: 사실 한 줄 + 원본 링크(있을 때). 봉투·키·검색 라벨은 기록에만. 리마인더가 첫 채택.
- 노드 일정 리마인더는 `~/.hermes/reminder-poller/calendar-events` 가 정확히 `on` 일 때만 돈다(기본 꺼짐, 마일스톤은 항상). 되돌리기: `printf on > ~/.hermes/reminder-poller/calendar-events`.
- 운영 경고 발신부 일곱 곳이 `fault=True` 로 짝 채널을 쓴다(짝 채널이 설정되지 않은 설치는 예전 목적지).
- 은행 시나리오는 자기를 은퇴시킨 스위치를 `retired_when: <스위치>=<값>` 으로 적고, 그 스위치 파일이 정확히 그 값이면 `RETIRED` 로 보고만 한다. 스위치 파일을 지우면 다시 돈다. personal-memory 드라이버는 원격 실행 HOME 을 자기 push 폴더 안으로 둔다.
- 스킬 배포 샌드박스는 peer 가 은퇴한 뒤 agent 의 실제 `~/.hermes/skills` 대신 `~/.hermes/skill-gate/sandbox-home` 에서 돈다. 배포 중 1분 동안 배포본 이름을 가리던 임시 사본이 없어져 `SHADOWS-GOVERNED` 경고가 다시 오지 않는다(2026-10-19 v2.6.2·v2.6.3 적용 때 짝 채널로 옴).
- 릴리스 전 리허설의 Hermes 제품 검사가 목록을 읽는 사이 사라진 프로세스를 "판독 불가" 로 세지 않는다(살아 있는 프로세스의 권한 거부는 여전히 거절).
