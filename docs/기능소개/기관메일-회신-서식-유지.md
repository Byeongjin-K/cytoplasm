# 기능 소개 — 기관메일 회신 서식 유지 (원본 HTML 인용 · 맑은 고딕 회신문)

**완료:** 2026-10-19 · **스킬:** `mail` · **모듈:** `skills/mail/scripts/mail_quote.py`, vendor `mailon/{writer,send,send_trigger,main}.py`

## 무엇을
기관메일 회신에 **원래 서식(표·색·굵기·글꼴)의 원문 인용**과 **맑은 고딕 10.5pt, 줄 간격 160% 회신문**을 선택할 수 있다. **v2.6.6에서는 기본 꺼짐**으로 배포한다. 형이 자기 메일함에서 시험 회신을 확인하기 전에는 다른 사람에게 새 서식을 쓰지 않는다. 꺼져 있으면 기존과 같은 평문 `--body`만 쓰며 새 메일·전달도 그대로다.

## 왜
소유자 결정(2026-10-19, Q46·Q47): "앞으로 메일 회신할 때, 기존 메일이 아래 달리는데 그 메일의 글씨체랑 띄어쓰기, 줄 간격 등이 좀 가시성이 안좋네. 원본 유지하면서 보낼 순 없나? 그리고 회신하는 글의 글씨체도 가시성 좋은것으로 선택하고 싶어."

원인은 두 가지였다. ① mailon 수집기가 원문 HTML 을 읽어 놓고도 저장할 때 글자(`get_text`)만 남겨서, 인용에는 줄과 칸이 흩어진 글자만 붙었다. ② 발송이 편집기에 `innerText` 로 평문을 넣어서, 편집기 기본 서식(굴림 10pt·150%)으로 나갔다.

## 핵심 동작 (불변식)
- 수집: mailon writer 가 원문 HTML 을 markdown 옆 `<같은 이름>.html` 로 함께 저장한다(새로 수집되는 메일부터). wrapper `get --body --with-html` 만 그것을 내준다(`--masked` 에서는 내주지 않는다).
- 릴리스 스위치: 릴리스 호스트 `~/.hermes/release-flags/mail-html-reply`의 **정확한 바이트 `on`**만 켜짐이다(개행도 거부, exit 4). 없으면 꺼짐이다. `mail-html-reply:on` 표면은 같은 HEAD의 릴리스 승인 해시에 묶이고 카드에는 **기관메일 회신 새 서식(원문 서식 인용·맑은 고딕) 켜기**가 표시된다. 승인 뒤 선언된 `push_file` 경로로 agent의 `~/.hermes/mail-html-reply.mode`를 원자 배치하고 릴리스 프로브가 다시 대조한다. 노드 표식을 손으로 만들지 않는다.
- 초안: 새 서식은 초안 생성 시에만 선택한다. 노드 표식이 켜져 있거나 형 주소 전용 `--format-test html`이면 `--body`와 `--body-html`을 함께 동결한다. `reply_format`(`html` 또는 `html-test`)·HTML argv·`quote_html`·`quote_format`도 승인 해시에 묶인다. 꺼짐에서는 이 새 필드 없이 예전 평문 argv와 해시 계약을 유지한다. 승인 후 스위치가 바뀌어도 이미 검토한 초안의 서식을 발송 시 바꾸지 않는다.
- 인용 HTML 정리(`mail_quote.sanitize_html`, 허용 목록): `<script>`·`<style>`·프레임·`<object>`·폼은 내용째 지운다. `on*` 이벤트와 목록 밖 속성도 지운다. 링크는 http(s)·mailto 만 남긴다. 이미지는 본문에 들어 있는 `data:image/…` 만 남기고, 원격·`cid:` 이미지는 alt 글자로 바꾼다(열자마자 바깥으로 요청이 나가지 않는다). CSS 선언 가운데 `url(`·`@import`·`expression(` 가 든 것도 지운다.
- 크기 상한: 정리한 원문 HTML 이 100,000바이트를 넘으면(argv 한 인자의 리눅스 상한은 128KiB) 평문 인용으로 내려간다. 원문 HTML 이 없을 때(이 변경 전에 수집된 메일)도 평문 인용을 줄바꿈·띄어쓰기를 지킨 HTML 로 보내고(줄은 `<br>`, 연속 띄어쓰기는 `&nbsp;`; `white-space:pre-wrap` 은 쓰지 않는다 — [본문 빈 줄 그대로](기관메일-본문-빈-줄-그대로.md)), 카드는 `- 원문 인용: 포함 (원본 서식 없이 글자만)` 으로 알린다.
- 발송: `send --body-html` 이 있으면 편집기 iframe 에 `innerHTML` 로 넣는다(재채움은 편집기 API `setContent`). 발송 검증은 그대로다: 평문 `--body` 의 첫 줄 표식이 실제 발송 내용에 있어야 하고(편집기가 `&`·`<`·`>` 를 엔티티로 바꾼 표기도 같은 글자로 본다), To·Cc·Bcc 는 정확히 일치해야 한다. 전체답장 Cc 규칙도 바뀌지 않았다.
- 실행 경계: 프리플라이트가 회신문을 고치면 HTML 본문도 고친 회신문+동결 인용으로 다시 만든다. Drive 공유 링크 자리(`<Drive 링크>`)는 두 본문에서 모두 링크로 바뀐다. 시험 회신도 긴 본문은 기존 첨부 승인 경로를 쓰고 시험 안내 줄은 카드에 남는다.

## 사용 시나리오
1. **(기본)** "3번 메일에 참석한다고 회신해줘" → 기존 평문 초안 → 카드 ✅ → 평문 회신. 형 주소를 수신자로 넣었더라도 시험 플래그가 없으면 자동으로 새 서식을 쓰지 않는다.
2. **(먼저 형 메일함에 시험)** 기존 `MAILON_ID`에서 형 기관주소를 확인하고, 원문 UID를 골라 `triage_cli.py compose --to <형 기관주소> --subject "Re: <원 제목>" --body "<시험 회신문>" --in-reply-to <uid> --format-test html`을 실행한다. 카드에 **새 서식 시험 회신(형 주소에만)**이 붙는다. 카드 ✅ 뒤에만 발송하며 형이 자기 메일함에서 원문 표·글꼴과 회신문을 확인한다. To·Cc·Bcc 중 하나라도 다른 주소이거나 형 주소를 확인할 수 없으면 초안 생성 전에 한 줄 사유와 exit 2로 거부한다. `draft --format-test html`도 원 발신자가 형인 경우에만 쓴다.
3. **(확인 후 전체 켬)** 릴리스 호스트 스위치를 `on`으로 두고 같은 HEAD의 릴리스 카드 ✅ → 이후 새 초안부터 새 서식. 원본 HTML이 없는 옛 메일은 글자 인용을 HTML로 감싸며, 추적 이미지·스크립트는 정리한다.

**되돌리기:** 호스트의 `~/.hermes/release-flags/mail-html-reply`를 지우고 다시 릴리스하면 이후 새 초안은 평문이다(기존 초안은 폐기 후 다시 만든다).
