# 작은 할 일 장부

수리 티켓·회의록 액션·제안서 카드를 사이토플라즘의 작은 SQLite 장부에
함께 넣는다(Q246·Q247). Hermes 작업 실행기 없이 카드 ID와 상태를 유지한다.
화면은 별도 앱이 아니라 기존 프로젝트 대시보드를 쓴다.

## 켜기와 되돌리기

릴리스 호스트의 `~/.hermes/release-flags/ledger`에 줄바꿈 없는 정확한 `on`을
두면 릴리스 카드에 다음 문구가 추가되고, `ledger:on` 표면이 승인 해시에 묶인다.

> 할 일 장부: 수리 티켓·회의록 액션·제안서 카드를 Hermes 보드에서 새 장부로(카드 그대로 옮김), 파일 삭제 후 재배포로 Hermes 보드 복귀

같은 HEAD의 릴리스 승인 뒤 배포가 세 호출자의 새 코드를 놓고 이관한다.
노드에서 사람이 실행할 준비 명령은 없다. 플래그가 없으면 기존 Hermes 명령과
출력 계약이 유지된다. 삭제 후 재배포는 호출자를 Hermes로 되돌리며 두 DB는
모두 보존한다. 새 장부에서 바뀐 상태를 옛 Hermes DB에 역으로 쓰지는 않는다.
되돌린 동안 Hermes 카드가 바뀌면 재전환은 이를 무시하지 않고 거부한다.

## 사용 시나리오

- 회의록에서 내 액션이 나오면 기존 회의록 처리 경로가 같은 `t_…` 형식의
  카드를 만들고 입력 대기로 둔다. 수리 티켓과 제안서 카드도 같은 장부에 들어간다.
  기존 승인·회의록 Drive 원장은 바뀌지 않는다.
- 기존 보드와 카드가 이관될 때 보관된 항목까지 모두 읽고 ID·본문·상태·시각·
  차단 근거·댓글·이벤트 등 `show --json` 전체와 중복 생성 방지 키를 보존한다.
  원본 DB의 전체/상태별 수와 CLI 내보내기, 장부 재조회 결과를 대조한다.
  하나라도 다르면 종료 코드 4로 멈추고 호출자는 Hermes에 남는다.
- 성공한 이관의 영수증은 장부 안에 보드 수·카드 수·상태별 수만 기록한다.
  재실행은 새 카드나 댓글을 복제하지 않는다. `kanban.db`는 읽기 전용으로
  조회하며 삭제하지 않는다.

## 장부와 명령

저장 위치는 계정의 `$XDG_STATE_HOME/autophagy/ledger.db`
(미설정이면 `~/.local/state/autophagy/ledger.db`), 권한은 0600이다.
런타임은 체크아웃과 `~/.hermes` 밖이며 명령·이관은 같은 로컬 잠금을 쓴다.

```bash
python3 -m automation.ledger boards list --json
python3 -m automation.ledger list --archived --json
python3 -m automation.ledger show <카드-id> --json
```

새 홈 스크립트·타이머를 만들지 않는다. 패키지는 서명 릴리스 트리로 배포되고,
전량 판정은 노드의 이관 완료/호출 모드를 다시 읽어 영수증 발급을 결정한다.
Hermes 설치·서비스를 제거하지 않으므로 기존 doctor·헬스체크의 전제는 유지된다.

관련: `automation/ledger/`, `automation/ledger_policy.py`,
`automation/deploy_all.sh`, `automation/project_board/`.
