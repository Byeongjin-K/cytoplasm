# Plaud 전문을 기억(recall) 근거로 교정하기

## 무엇을 · 왜

다 만든 Plaud 전사본을 노트로 처음 저장하기 직전에 고친다. 노드의 기억(recall)에서 그 회의와
관련된 노트·메일 조각을 찾고, 계정의 주 모델이 그 근거와 문맥으로 사람 이름·기관명·과제명·용어의
잘못 받아 적은 낱말만 고친다. 바뀐 낱말은 노트 안 표로 남는다.

음성 인식은 고유명사와 전문 용어를 자주 틀린다. 인식 전에 힌트를 주는 방식은 2026-10-22 실측에서
녹음에 없는 이름·문장을 전사본에 지어 넣었다. 그래서 인식이 끝난 전사를 고치고,
다른 사람 이름으로 바꾸는 실수는 이름 가드로 막는다.

기본은 꺼져 있다. [동결 전 교정 훅](plaud-전사-동결전-교정.md) 설정을 노드에 두어야 켜진다.

## 켜는 법 (노드 소유자)

`~/.hermes/plaud-sync/transcript-corrector.json`:

```json
{
  "argv": ["/usr/bin/python3",
           "/srv/autophagy-agent-current/automation/plaud_sync/recall_correct.py",
           "--recall-cli", "/srv/autophagy-skills/live/recall/scripts/recall_cli.py"],
  "timeout_seconds": 1200
}
```

모델은 코드에 적지 않는다. 주 모델·omo 중계 설정을 그대로 따른다(`codex_llm`). 파일을 지우면 다음 녹음부터 원문 그대로 저장된다.

## 동작

1. recall 검색 두 번: 회의 이름, 그리고 전사에 자주 나온 긴 낱말.
2. 주 모델은 전사를 다시 쓰지 않고 고칠 낱말 목록(줄·원래·바른 표기·근거)만 돌려준다.
   모델이 고친 새 낱말은 한 번 더 recall로 확인한다(동시에, 많아야 10개, 가드에 걸릴 낱말부터, 30초 안에 답이 온 것만).
   음절 하나짜리 말(관로의 「로」 같은)은 조사로 떼지 않는다.
3. 이름 가드: 원래와 바른 표기의 자모 거리가 `max(허용치, 2)`를 넘으면 버린다.
   원래 낱말이 기억 조각에 그대로 있으면(이미 아는 실제 이름·낱말) 바꾸지 않는다.
   기억이 새 낱말을 적고 있으면 소리 차이를 5까지 허용한다. 앞뒤나 낱말 안에 님·박사·위원 같은 호칭이 붙은 사람 이름은
   기억에 있어도 원래 가드 그대로다.
   시각·화자 앞부분, 머리글, 구조 줄은 손대지 않는다.
   고친 낱말 끝 받침이 바뀌면 바로 뒤 조사 짝(은/는·이/가·을/를·과/와·이랑/랑·으로/로, ㄹ 받침은 로)을 맞춘다.
   짝 목록에 없는 말(의·에·이라 등)은 그대로 둔다.
4. 노트 `## 전문` 바로 위 `## 교정 기록`에 「시각 | 원래 | 바뀐 | 근거」 표와 가드가 막은 수가 붙는다.
   표는 원문과 교정본의 낱말 차이로 만들므로 바뀐 곳이 빠질 수 없다. 원래 칸이 고치기 전 전사다.
   근거 칸은 모델의 말이 아니라 글자로 정한다. 바뀐 낱말이 기억 조각에 있으면 「기억: <제목>」,
   같은 전사의 다른 곳에 이미 그렇게 적혀 있으면 「같은 전사 다른 곳」, 둘 다 아니면 「문맥」이다.

## 사용 시나리오

- 정상: 형이 Plaud로 회의를 녹음한다 → 노트가 저장될 때 과제 용어·기관명이 바르게 나오고,
  노트 안 표에서 「오토파즈 → 오토파지 · 기억: 과제 노트」처럼 무엇을 왜 바꿨는지 본다.
- 이름 보호: 모델이 어떤 사람 이름을 기억에 있는 다른 사람 이름으로 바꾸자고 하면 가드가 버리고,
  표에 「이름 가드가 막은 교정 N건」으로 남는다.
- 실패: recall이 안 되면 근거 없이 문맥으로만 고친다. 모델 호출·답 해석이 실패하거나 시간을 넘기면
  노트는 원문 그대로 제때 저장된다(훅의 fail-open).

## 실측 (2026-10-22, 50분 회의 1건, 노드 agent 계정, 실제 recall·주 모델·훅, 최종 코드 2회)

| 항목 | 1회 | 2회 |
|---|---|---|
| 바뀐 곳(노트 표 줄) | 32 | 34 |
| 맞게 고침 | 32 | 33 |
| 잘못 바꿈 | 0 | 0 |
| 확인 불가 | 0 | 1 |
| 근거 「기억」 / 「같은 전사 다른 곳」 / 「문맥」 | 6 / 22 / 4 | 6 / 26 / 2 |
| 이름 가드가 막은 제안 | 12 | 8 |
| 알려진 오기 8묶음 남은 수 | 37 → 10 | 37 → 11 |
| 어색한 조사 | 0 | 0 |
| 시간(훅 전체) | 91초 | 84초 |

- 시간은 recall 회의 검색 20~35초, 주 모델 약 25~30초, 새 낱말 기억 확인 30초(상한)다. recall 서비스가 한 번에 15~20초 걸리고 동시 요청을 차례로 처리해, 30초 안에 확인되는 낱말은 3개쯤이다.
- 비용: 주 모델 호출 1회(입력 약 2만 자, 출력 약 2천 자, 계정 구독 경로) + recall 검색 2회 + 확인 검색 최대 10회.
- 채점은 녹음을 다시 듣지 않고 문맥과 같은 회의를 따로 받아쓴 전사를 대조한 한 사람의 판정이다. 같은 입력도 실행마다 고친 곳이 다르다.

## 관련

- `automation/plaud_sync/recall_correct.py`: recall 조회·모델 목록·이름 가드·적용
- `automation/plaud_sync/transcript_corrector.py`: 훅 경계·구조 검사·바뀐 낱말 표
- `automation/plaud_sync/note.py`: `## 교정 기록` 절
- `tests/unit/test_plaud_recall_correct.py` · `tests/unit/test_plaud_transcript_corrector.py`: 합성 입력 시험
- 승인 게이트는 관여하지 않는다. 노트 쓰기는 기존 Plaud 카드·자동 쓰기 경로를 그대로 탄다.
