# 끈 정기 작업은 삭제한다

## 무엇을·왜

2026-10-19 소유자 “끄지 말고 삭제” 결정으로 09:00 비용 보고와
메모리 큐레이터·이동 예약 작업을 제거했다. Q282 “일단 이 기능 없애자 일정 기능과 중복이야”로
캘린더·마일스톤 알림 폴러도 전체 삭제했다. 새 스위치는 없고 복원 근거는 git 이력이다.

회의록에는 마일스톤을 그대로 기록하지만 별도의 `milestones.yaml`을 쓰지 않는다.
메모리 공개 CLI·공유 타입과 기존 피어 결정 재생 경로는 남기고,
삭제한 에이전트 잡만 쓰던 발견·승인 게시·실행 모듈은 함께 제거했다.

## 릴리스에서 정리되는 것

`automation/retired_jobs/deploy-manifest.txt`의 필수 derived 선언이
`memory-curator-watch`·`memory-relocate-watch`·`reminder-poller`의
생성된 사용자 타이머·서비스 파일을 정리한다. 단순 `policy=retired`는
잔존 관측만 하므로 실제 제거에는 쓰지 않는다. 활성 릴리스 HEAD가 일치해야 실행하며,
유닛의 정지·비활성을 확인할 수 없으면 첫 삭제 전에 거부한다.

알림 유닛 파일 제거·daemon-reload·정지 재조회 뒤에만 agent 홈의
정확한 `state/reminders.db`·`state/milestones.yaml` 두 파일을 삭제한다.
상태 디렉터리와 파일의 심링크는 거부하고, 디렉터리 FD 안의 고정 파일명만 지운다.
원본 메모리·메모리 상태·백업·recall은 건드리지 않는다. 이미 없는 파일은 완료이고 재실행은 무동작이다.

## 사용 시나리오

- 소유자가 릴리스를 승인하면 기존 선언형 전량 배포가 멈춘 세 작업의 생성 유닛을 제거하고 알림 파생 파일 둘도 정리한다.
- 같은 릴리스를 다시 적용해도 파일·스케줄을 되살리지 않는다.
- 타이머나 서비스가 아직 활성 상태이거나 파일이 심링크면 삭제하지 않고 릴리스 검증에 문제를 남긴다.
- 이후 회의록을 만들면 문서의 마일스톤은 남지만 별도 알림용 YAML이나 D-day 알림은 생기지 않는다.
