# 릴리스 짧은 승인과 상세 조회

## 무엇을
신규 v7 승인 카드는 최대 12줄·1900자로 버전, 변경 요약, 승인할 스위치와 운영자 경보,
전체 승인 해시 및 결정 방법을 보여 준다. 긴 변경 상세는 자동 게시하지 않는다.

## 왜
소유자가 승인할 때마다 전체 커밋 설명이 여러 메시지로 쏟아져 필요한 결정이 묻혔다.
짧은 카드로 승인하고, 상세는 잃지 않은 채 필요할 때만 읽는다.

## 사용 시나리오
- 릴리스를 요청하면 호스트가 `~/.hermes/release-notes/<sha>.details.md`에 전체 번들·커밋을
  0600으로 저장하고 카드만 올린다. 형의 승인 뒤 기존 `ensure_release_note`가 초안과 상세를
  합쳐 해당 태그의 공개 GitHub Release 본문으로 발행한다.
- 형이 "v2.0.1에서 뭐 바뀌었어?"라고 물으면 유돌이 노드 게이트
  `release-notes v2.0.1`을 실행해 그 버전의 노트를 올린다. 평소에는 올리지 않는다.
- 태그 형식 오류는 조회 전에 거절한다. 공개 Release가 없거나 네트워크·크기 제한에 걸리면
  `YOODORI-GATE-REFUSED release notes unavailable`(exit 2)이다.
  발행이 실패해도 로컬 상세는 남는다. `RELEASE_NOTES_DIR` 설정 시 초안과 같은 폴더를 쓴다.

## 관련
`automation/release_notes.py`, `release_spec.py`, `release_spec_message.py`,
`release_request_gate.py`, `release_tag_lib.sh`, `yoodori_gate/yoodori_read_gate.py`,
`dori/roles/yoodori/AGENTS.md.tmpl`.
승인 해시·표면·nonce는 불변이며 기존 lifecycle과 소유자 승인 게이트를 재사용한다.
저장된 v1~v6 카드는 예전 바이트로 재생한다.

## 적용 완료 통지는 현재 조치만
2026-10-18 소유자 요청에 따라 완료 통지는 버전·HEAD와 실제 남은 조치만 알린다.
OMO 대화 모델이 아닌 Hermes 게이트웨이의 주 모델·폴백·반복 한도·agent/peer 비교는
조회하거나 표시하지 않는다. 옛 발신자의 `--models` 인자는 받아도 무시한다.

영수증의 `held` 사유가 `retired` 또는 `-retired`로 끝나면(예: `peer-retired`)
의도한 은퇴이므로 소유자 조치 안내에서 뺀다. 영수증 원본은 보존하며
`roster-required` 등 다른 보류와 실패·확인 불가 안내는 계속 보여 준다.
예를 들어 peer 은퇴만 남으면 "보류 1건" 없이 적용 완료 한 줄만 알린다.
관련: `release_applied_notice.py`, `release_applied_state.py`, `deploy_receipt.py`.

## v8: 노트 첫 줄 요약 · 바뀐 스위치만 (2026-10-19)
v2.3.0 카드가 릴리스 호스트의 상시 스위치(유산 정리·P5·자동 쓰기 7종·도리 전환·게이트웨이 멈춤 등)를 매번 다시 실어 길어졌다. 이제 카드는
- 첫 줄 요약을 `release.sh --notes-file` 노트의 첫 줄(`# …`)에서 가져오고,
- 이번 릴리스에서 새로 켜지거나 값이 바뀐 스위치만 줄로 보여 주며,
- 직전 릴리스와 같은 스위치는 「계속 켜져 있는 스위치 N개(바뀐 것 없음)」 한 줄로 접는다(자세한 건 유돌에게).
승인 해시는 예전처럼 모든 표면을 묶는다 — 보이는 글만 줄었다. 직전 카드의 표면을 이 PC가 모르면(첫 v8 릴리스) 예전처럼 전부 보여 준다. 시험 `tests/unit/test_release_card_v8.py`.
