# Plaud 전문을 형의 교정 장부로 고치기

## 무엇을 · 왜

다 만든 Plaud 전사본을 노트로 처음 저장하기 직전에 고친다. 형이 전에 지적한 낱말(교정 장부)을 먼저 적용하고,
계정의 주 모델이 장부와 문맥으로 사람 이름·기관명·과제명·용어의 잘못 받아 적은 낱말만 고친다.
바뀐 낱말은 노트 안 표로 남는다.

음성 인식은 같은 이름·용어를 회의마다 같은 식으로 틀린다. 형이 한 번 지적한 것은 다음 녹음부터
바로 맞게 나오게 하려는 기능이다(형 2026-10-22). 처음에는 노드 기억(recall)을 근거로 썼으나,
그 단계는 형 지시로 뺐다.

기본은 꺼져 있다. [동결 전 교정 훅](plaud-전사-동결전-교정.md) 설정을 노드에 두어야 켜진다.

## 교정 장부

- 기존 용어집을 그대로 쓴다. 정본은 Drive `autophagy/라이프로그/용어집.csv`(회의록은 `autophagy/회의록/용어집.csv`)이고
  한 줄이 「틀린표기,올바른표기」다. Drive 발행이 꺼진 노드는 노드 사본(`~/.hermes/term-glossary/`)이 장부다.
- 형이 노트 표나 전문을 보고 유돌에게 "A가 아니라 B야"라고 말하면, 유돌이 게이트 명령
  `glossary-add A B [--kind lifelog|meeting]`(끝에 형 글 좌표)로 한 줄을 더한다. 같은 틀린 표기가 이미 있으면 바른 표기를 새것으로 고친다.
  형 본인 글이 근거여야 하고, 하루 요약에 「용어집 A → B」로 남는다. 형 Drive 안 쓰기라 카드는 없다.
- 지금 장부는 `glossary-list [--kind lifelog|meeting]` 로 본다. 한 줄에 「틀린표기,올바른표기」이고, 종류를 안 주면 라이프로그와 회의록을 합쳐 보인다(같은 틀린 표기는 회의록이 이긴다).

## 켜는 법 (노드 소유자)

`~/.hermes/plaud-sync/transcript-corrector.json`:

```json
{
  "argv": ["/usr/bin/python3",
           "/srv/autophagy-agent-current/automation/plaud_sync/glossary_correct.py"],
  "timeout_seconds": 600
}
```

모델은 코드에 적지 않는다. 주 모델·omo 중계 설정을 그대로 따른다(`codex_llm`). 파일을 지우면 다음 녹음부터 원문 그대로 저장된다.

## 동작

1. 장부의 3음절 이상 쌍은 모델 앞에서 바로 바꾼다(형이 준 쌍이라 거리 가드 예외). 시각·화자 앞부분, 머리글, 구조 줄은 손대지 않는다.
2. 2음절 이하 쌍(일반 낱말과 겹칠 수 있는 것)은 바로 바꾸지 않고 모델에게 「형 교정 장부」 힌트로만 준다.
3. 주 모델은 전사를 다시 쓰지 않고 고칠 낱말 목록(줄·원래·바른 표기)만 돌려준다.
4. 이름 가드: 모델이 고친 낱말의 자모 거리가 `max(허용치, 2)`를 넘으면 버린다. 형이 장부에 바른 표기로 적은 낱말은 바꾸지 않는다.
5. 고친 낱말 끝 받침이 바뀌면 바로 뒤 조사 짝(은/는·이/가·을/를·과/와·이랑/랑·으로/로, ㄹ 받침은 로)을 맞춘다.
   음절 하나짜리 말과 짝 목록에 없는 말(의·에·이라 등)은 그대로 둔다.
6. 노트 `## 전문` 바로 위 `## 교정 기록`에 「시각 | 원래 | 바뀐 | 근거」 표와 가드가 막은 수가 붙는다.
   표는 원문과 교정본의 낱말 차이로 만들므로 바뀐 곳이 빠질 수 없다. 근거 칸은 글자로 정한다.
   장부에 있는 쌍이나 바른 표기면 「형 교정 장부」, 같은 전사의 다른 곳에 그렇게 적혀 있으면 「같은 전사 다른 곳」, 둘 다 아니면 「문맥」이다.

## 사용 시나리오

- 정상: 형이 노트 표에서 「오토파즈」가 그대로인 것을 보고 유돌에게 "오토파즈가 아니라 오토파지야"라고 말한다.
  유돌이 장부에 한 줄을 쌓고, 다음 녹음부터는 표에 「오토파즈 → 오토파지 · 형 교정 장부」로 바로 고쳐 나온다.
- 이름 보호: 모델이 어떤 사람 이름을 소리가 먼 다른 이름으로 바꾸자고 하면 가드가 버리고, 표에 「이름 가드가 막은 교정 N건」으로 남는다.
- 실패: 장부를 못 읽으면 장부 없이 문맥으로만 고친다. 모델 호출·답 해석이 실패하거나 시간을 넘기면
  노트는 원문 그대로 제때 저장된다(훅의 fail-open). 잘못된 장부 줄(쉼표·등호·줄바꿈, 40자 초과, 같은 낱말 쌍)은 쌓이지 않는다.

## 실측 (2026-10-22, 50분 회의 1건, 노드 agent 계정, 실제 주 모델·훅)

| 항목 | 장부 없음(문맥만) | 장부 15쌍 1회 | 장부 15쌍 2회 |
|---|---|---|---|
| 바뀐 곳(노트 표 줄) | 32~34 | 47 | 38 |
| 잘못 바꿈 | 0 | 0 | 0 |
| 확인 불가 | 0~1 | 1 | 0 |
| 알려진 오기 8묶음 남은 수 | 37 → 10~11 | 37 → 3 | 37 → 3 |
| 근거 「형 교정 장부」 | — | 39 | 38 |
| 시간(훅 전체) | 84~91초(옛 recall 단계 포함) | 27초 | 26.5초 |

- 장부 15쌍은 같은 회의의 오기를 형이 한 번씩 지적했다고 가정해 만든 것이라 상한이다. 장부가 빈 첫 녹음은 이득이 없고,
  같은 과제를 반복해 녹음할수록 쌓인다.
- 비용: 주 모델 호출 1회(입력 약 2만 자, 출력 약 1천 자, 계정 구독 경로).
- 채점은 녹음을 다시 듣지 않고 문맥과 같은 회의를 따로 받아쓴 전사를 대조한 한 사람의 판정이다.

## 관련

- `automation/plaud_sync/glossary_correct.py`: 장부 적용·모델 목록·이름 가드·조사 맞춤
- `automation/plaud_sync/transcript_corrector.py`: 훅 경계·구조 검사·바뀐 낱말 표
- `automation/term_glossary.py`: 장부 읽기·`add`(유돌 `glossary-add`)·`list`
- `automation/yoodori_gate/yoodori_read_gate.py`: `glossary-add`·`glossary-list`
- 시험: `tests/unit/test_plaud_glossary_correct.py` · `test_plaud_transcript_corrector.py` · `test_term_glossary_add.py` · `test_yoodori_glossary.py`
- 승인 게이트는 관여하지 않는다. 노트 쓰기는 기존 Plaud 카드·자동 쓰기 경로를 그대로 탄다.
