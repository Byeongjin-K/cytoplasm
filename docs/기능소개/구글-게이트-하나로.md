# Google 자격증명을 노드 게이트 하나로

## 무엇을

노드 전용 Google 게이트 설정, `gws` 토큰 shim, doctor 점검과 소유자용 설치 블록을 준비한다.
**기본 꺼짐**이다. 이 PR을 받아도 설치·동의·shim 교체가 자동 실행되지 않는다.
실제 전환은 지원 포크가 고정된 뒤 **별도 소유자 승인 카드**로 진행한다.

## 왜

PC 게이트와 노드 `gws`가 각자 Google 자격증명을 보관하면 회수·동의·장애 확인이 갈라진다.
목표는 같은 포크 `gate.py`가 노드의 독립 시스템 계정에서 두 OAuth 동의를 보관하는 것이다.
기본 grant는 발송 권한 없는 역방향 API용, `jobs` grant는 기존 배치의 12개 권한용이다.
그 목록은 `automation.doctor.guides.GWS_SCOPES`를 그대로 재사용한다.
PC는 나중에 키 없이 SSH 소켓 터널로 중계하며 Google 외부 발송 카드는 노드 게이트만 게시한다.
이 준비 작업은 기존 메일·일정 카드나 PC 설정을 변경하지 않는다.

## 사용 시나리오

- **정상**: 나중에 소유자가 전환을 승인하고 운영자가 게이트·`jobs` 동의를 준비한다.
  agent 계정에서 shim을 설치하면 기존 작업은 같은 `gws` 명령을 계속 쓴다.
  shim은 루프백 게이트에서 짧은 토큰을 받아 환경변수에만 넣고 원래 바이너리를 실행한다.
  doctor는 게이트가 반환한 범위로 토큰 연결을 확인한다.
- **게이트 정지·미동의·UID 거부**: shim은 `GOOGLE-GATE-TOKEN-FAIL` 한 줄과 종료코드 2로 끝난다.
  원래 `gws`는 실행하지 않으며 옛 자격증명으로 우회하지 않는다. doctor는 고장과 노드 게이트 상태 확인을 안내한다.
- **다른 파일·변조된 바이너리**: 설치·제거는 덮어쓰지 않고 거부한다. 제거는 보관된 SHA가 맞는
  원래 바이너리만 되돌린다. 기존 Google 동의 파일은 삭제하지 않는다.

## 준비와 되돌리기

설정만 출력(값은 설치별 인자이며 비밀 자체를 받지 않는다):

```sh
python3 -m automation.google_gate render-config \
  --relay-uid "$RELAY_UID" --agent-uid "$AGENT_UID" --operator-uid "$OPERATOR_UID" \
  --owner-id "$OWNER_ID" --owner-guild "$OWNER_GUILD" --owner-email "$OWNER_EMAIL" \
  --approval-channel "$APPROVAL_CHANNEL" --bot-token-file /var/lib/dori-gate/owner-bot-token
```

`--owner-email`은 여러 주소 또는 반복 인자를 받는다. 선택 vault는
`--vault-dir "$VAULT_DIR" --vault-remote "$VAULT_REMOTE" --vault-key "$VAULT_KEY" --vault-prefix "$VAULT_PREFIX"`
네 인자를 모두 준다. `--state` 기본값은 `/var/lib/dori-gate`다.

소유자용 루트 블록(지금 실행하지 않음):

```sh
sh docs/guide/google-gate-root-block.sh --dry-run \
  --fork-checkout "$FORK_CHECKOUT" \
  --relay-uid "$RELAY_UID" --agent-uid "$AGENT_UID" --operator-uid "$OPERATOR_UID" \
  --owner-id "$OWNER_ID" --owner-guild "$OWNER_GUILD" --owner-email "$OWNER_EMAIL" \
  --approval-channel "$APPROVAL_CHANNEL" --bot-token-file "$BOT_TOKEN_FILE" \
  --client-secret-file "$CLIENT_SECRET_FILE" --relay-key-file "$PC_PUBLIC_KEY_FILE" --pc-ip "$PC_IP"
```

모드 생략도 dry-run이다. 임시 디렉터리에서 고정 HEAD의 Python 자산·유닛·설정을 검사하고 지운다.
`--apply`만 root 쓰기다. 시스템 계정(기본 `dori-gate`, `dori-gate-relay`, nologin),
`/opt/dori-gate`, `/etc/dori-gate`, 0700 상태 디렉터리, 0600 비밀 사본과 제한된 relay 공개키를 준비하고
게이트·요약 타이머를 켠다. nft 유닛·PC 터널·Google 동의·agent shim은 설치하지 않는다.
fork HEAD가 `dori/pin.toml`과 다르면 거부하며, 설치 자산은 작업 트리가 아니라 그 커밋 객체에서 읽는다.
고정 커밋의 `gate.py`가 전달 모드·jobs 묶음(포크 #116)보다 옛것이면 `fork-gate-too-old`로 거부한다 — 그래서 pin 을 올리는 릴리스가 먼저다.
루트 블록의 `--state`는 `/var/lib/<gate-user>`여야 한다. 선택 vault는 `/home`·`/root` 밖의 전용
디렉터리를 쓰며 서비스 쓰기 허용 경로에도 넣는다. vault 키도 dry-run에서 파일 존재를 확인한다.
`sh docs/guide/google-gate-root-block.sh --rollback`은 root에서 유닛만 끄고 상태·동의를 보존한다.

포크 계약: `skills/dori-mode/setups/egress-gate/{gate.py,gatectl.py,summary.py,systemd/…}`와
`--config /etc/dori-gate/config.json` 인터페이스를 사용한다. 고정 포크가 null listener,
`token_clients`, `grants.jobs`와 `/_gate/access-token?grant=jobs`를 지원해야 실제 전환할 수 있다.
이 PR은 포크 pin을 올리지 않는다.
