# Plaud 전문을 첫 저장 전에 교정하기

## 무엇을 · 왜

노드가 명시적으로 켠 경우에만 외부 명령으로 lifelog `## 전문`을 교정한다.
교정은 노트 본문·SHA·승인 해시를 동결하기 전에 끝나므로, 첫 Obsidian 저장부터
교정본이 들어간다. 저장 뒤 덮어쓰는 작업은 없다. 기본은 꺼짐이며 기존 노트 바이트는 같다.
`~/.hermes/plaud-sync/transcripts/`의 원본 파일은 증거로 그대로 보존한다.

## 설정과 명령 계약

노드 소유자가 `~/.hermes/plaud-sync/transcript-corrector.json`을 둔다.
이 변경은 설정을 자동 생성하거나 릴리스 스위치를 바꾸지 않는다.

```json
{
  "argv": ["/absolute/path/to/transcript-corrector", "--stdin"],
  "timeout_seconds": 300
}
```

- JSON 객체에서 `argv`는 필수다. 비어 있지 않은 문자열 배열이며 각 원소는
  공백만이거나 NUL을 포함할 수 없다. `timeout_seconds`는 선택이며
  3,600 이하인 유한한 양수(불리언 제외), 기본 300초다.
  무한 대기나 플랫폼 시간 제한 오버플로를 피하려고 상한을 둔다. 다른 키는 거부한다.
- 셸 없이 argv 그대로 실행한다. `~`, 환경변수, 셸 문법을 확장하지 않는다.
  실행 파일과 필요한 인자는 노드가 정한다.
- stdin: UTF-8 원문 전사 마크다운. 로컬 전사는 헤더까지 포함한 원본 파일 전체,
  클라우드 직접 저장·폴백은 클라우드 전사 마크다운이다.
- env: 기존 자식 환경을 물려주고 `PLAUD_RECORDING_ID`와 `PLAUD_NOTE_TITLE`을
  설정한다. 제목은 실제 예정 경로의 확장자 없는 stem이며 재처리는 고정 경로를 따른다.
  `PLAUD_CORRECTION_REPORT`는 명령이 근거를 적을 임시 파일 경로다(선택, JSON
  `{"evidence":[{"before","after","evidence"}],"rejected":N}`). 형식이 틀리면 원문으로 저장한다.
- exit 0의 UTF-8 stdout만 교정본으로 받는다. stdout에는 전사 마크다운만 쓴다.
  명령의 stderr는 수집하지 않고 버린다. 원문·교정문·명령 오류 본문은 로그에 싣지 않는다.
- 출력 검증: 비어 있지 않고 `splitlines(keepends=True)`의 줄 수가 같다.
  첫 `---` 줄이 있으면 그 줄까지 헤더가 바이트 그대로여야 한다.
  이후 빈 줄과 `#`, `- 화자:`로 시작하는 구조 줄, 시각만 있거나 시각+화자 머리줄
  (`[00:00:27] 화자1`, `[00:00:27] 화자1 · 이름`), 시각으로 시작하지 않는 `[` 줄은 그대로여야 한다.
  회의 줄 `[00:01:02] 화자1: 말`과 `[00:01:02] 말`은 시각·화자 앞부분이 바이트 그대로일 때
  뒤의 말만 고칠 수 있다(2026-10-22, 전에는 이 줄을 전부 거부했다).
  발화 줄을 빈 줄이나 그 접두사의 새 구조 줄로 만들 수 없다.
  화자·시각·문서 구조를 고치거나 헤더에 교정 영수증을 추가하는 래퍼는 이 계약에 맞춰야 한다.
  이 검사는 구조만 보장하며 문장 의미의 정확도를 보증하지 않는다.

## 사용 시나리오 · 실패

1. 설정 없음: 명령 실행·진단 없이 예전과 같은 원문 노트를 만든다.
2. 설정 있음: 추출이 제목을 정함 → 명령이 발화 줄의 오기를 교정 →
   전문을 렌더 → 그 본문의 SHA와 action hash 동결 → 기존 승인/자동 쓰기 경로로 첫 저장.
   바뀐 곳이 있으면 노트 `## 전문` 바로 위 `## 교정 기록`에 「시각 | 원래 | 바뀐 | 근거」 표가 붙는다.
   표는 명령의 보고가 아니라 원문과 교정본의 낱말 차이로 만든다. 보고하지 않은 교정도 표에
   남고(근거 「문맥」), 「원래」 칸이 고치기 전 전사다. 바뀐 곳이 없으면 표가 없고 노트는 원문과 같다.
   형 교정 장부로 고치는 명령은 [Plaud 전문 장부 교정](plaud-전사-장부-교정.md).
3. 설정 읽기·파싱, 명령 시작·종료, UTF-8 해석, 구조 검증 중 실패하면 원문으로 저장한다.
   제한 시간 초과는 명령의 프로세스 그룹을 종료하고 원문으로 진행한다.
   노트를 유실하거나 교정 실패 때문에 재시도 상태로 막지 않는다.
   워처 stderr에 `PLAUD-TRANSCRIPT-CORRECTOR recording_id=… fallback reason=…`를 남긴다.
   사유는 `config-read`, `invalid-config`, `command-error`, `exit:<종료코드>`,
   `timeout`, `invalid-output` 중 하나다. 상태 레코드에는 별도 필드를 추가하지 않는다.
4. 설정 파일을 삭제하면 다음 생성부터 기본 동작으로 돌아간다. 이미 동결·저장된 노트는
   소급 수정하지 않는다.

요약·사람·장소·결정·할 일 추출과 생성 제목은 **원문 기준**이다. 추출이 예정 제목을
정하므로 그 뒤에 훅을 둔다. 두 번째 모델 호출과 제목 변경을 피하고, 교정은 전문에만
적용한다. 기본 용어집 정책(원문 인용 불변)의 예외는 이 명시적 노드 opt-in뿐이다.

## 관련

- `automation/plaud_sync/transcript_corrector.py`: 명령·검증·실패 진단 경계
- `note.corrected_lifelog_note` → `binding.finalize`: 교정 뒤 실제 본문 해시 동결
- `transcribe_promote`: 로컬 원본 전체를 훅에 주되 보관 파일은 바꾸지 않음
- [Plaud 동기화](plaud-lifelog-동기화.md) · [노트 자동 쓰기](plaud-노트-자동-쓰기.md)
- `tests/unit/test_plaud_transcript_corrector.py`: 합성 입력만 쓰는 회귀 시험

릴리스 노트: Plaud 전문의 첫 저장 전 교정 명령을 노드별 opt-in으로 지원하며,
기본 원문 보존·원본 파일·기존 승인/자동 쓰기 동작은 유지한다.
