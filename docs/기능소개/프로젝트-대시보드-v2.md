# 프로젝트 대시보드 (v2: 메일 분석 → 담당자 승인 → 프로젝트 데이터 → 웹 대시보드)

## 무엇을

v1 이 이미 모아 둔 기관 메일(본문·원본 첨부)과 완성된 회의록을 모델이 읽고 **프로젝트 분류·할 일·기한을
제안**한다. 제안은 소유자 승인 카드로 올라가고, 소유자가 ✅ 한 것만 프로젝트 데이터(프로젝트·담당자·할 일·
기한)에 들어간다. 그 데이터는 노드 로컬 웹 대시보드(현황·TODO 체크·일정·원문/첨부 링크)로 보이고, 할 일을
체크하거나 명령으로 진행을 기록하면 데이터가 갱신된다.

## 왜

메일로 오는 요청·기한이 프로젝트별로 정리되지 않아 사람이 다시 읽고 옮겨 적어야 했다. 모델이 초안을 만들되
**모델이 쓴 것이 곧바로 데이터가 되지 않게** 승인 카드를 거치게 했다. 모델은 오토파지 주 모델과 같다(계정
`~/.hermes/config.yaml` 이 정한다). 로컬 LLM 서버(OpenAI 호환, vLLM·llama.cpp)로 바꾸는 것은 설정 한 줄이다.

## 사용 시나리오

**정상 흐름**

1. 기관 메일 「프로젝트A 중간보고 자료 요청」이 v1 동기화로 들어온다.
2. 분석 cron(설정 `analyze.enabled: true` 일 때 30분마다) 또는 에이전트가
   `python3 -m automation.project_board analyze --mail <uid>` 를 돌린다 → 「프로젝트 제안 검토」 카드가
   요청별 승인 스레드에 올라간다(프로젝트·요약·할 일 목록(담당·기한·기한 근거)·근거 메일·분석 모델·action_hash).
3. 소유자가 스레드에 "1번 기한 24일로, 2번은 빼" 라고 답한다 → 에이전트가
   `revise <제안> --set-due 1=2026-10-24 --drop 2` → 옛 카드는 지워지고 같은 스레드에 2판 카드가 올라간다.
4. 소유자가 ✅ → 2분 안에 워처가 그 판만 데이터에 반영하고 대시보드를 다시 만든 뒤 스레드에 결과를 남기고 닫는다.
5. 대시보드에서 할 일을 체크하면 완료로 기록된다(명령: `progress <todo_id> --status 완료 --note 제출함`).

**거부·실패 흐름**

- ⛔ → 데이터는 바뀌지 않고 스레드가 「⛔ 취소」로 닫힌다. ✅ 와 ⛔ 가 함께면 취소가 이긴다.
- 프로젝트와 무관한 메일(광고·자동 알림)은 카드를 만들지 않는다(`PROPOSAL-SKIP reason=unrelated`).
- 모델 답이 JSON 이 아니거나 기한이 날짜가 아니면 추측하지 않고 실패한다(재시도 대상, 다음 틱에 다시).
- 이미 반영된 제안은 고치지 않는다 — 바꾸려면 새 제안이다.
- 승인 뒤 디스크의 제안 파일이 바뀌면 해시가 맞지 않아 반영하지 않는다.

## 운영 전 분류 점검

`python3 -m automation.project_board dryrun --days 28 --out <비공개 경로>.jsonl` — 실제로 받은 최근 메일을 분석만 해서
결과 파일 하나에 쓴다(카드·데이터·대시보드 없음, 메일함 읽기만). 과제 목록(별칭 포함)은 노드 설정 `projects` 에 두고,
맞는 과제가 없으면 `미분류` 로 남는다.

## 대시보드 보는 법 (로컬 전용)

- 파일: 노드 agent `~/.hermes/project-board/dist/dashboard.html`(자체 완결 HTML, 외부 연결 없음).
- 웹: 사용자 유닛 `autophagy-project-board` 가 `127.0.0.1:8810` 에만 연다(다른 주소 bind 는 거부).
  워크스테이션에서 `ssh -L 8810:127.0.0.1:8810 <노드>` 후 `http://127.0.0.1:8810/?t=<토큰>`
  (토큰: `~/.hermes/project-board/serve.token`). 한 번 열면 쿠키로 유지된다.
- 일일 요약 메일: `digest --request-mail` 이 그날 스냅샷 HTML 을 첨부한 **메일 승인 카드**를 올린다. 발송은 그 카드 ✅ 뒤 메일 워처가 한다.

## 관련

- 코드: `automation/project_board/`(분석·제안·승인 어댑터·워처·저장소·대시보드·서버·CLI), 프롬프트 `prompts/project-analysis-v1.md`
- 승인: 새 kind `project-board`(소유자 대화 채널 요청별 스레드), 공용 `approval_lifecycle`·`origin_notice`·`thread_pointer`
- 설정·운영: [가이드](../guide/프로젝트-대시보드.md)
- 시험: `tests/unit/test_project_board_*.py`, 샌드박스 `automation/project_board/scenario.sh`
