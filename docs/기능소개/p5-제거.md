# P5 제거

멈춰 둔 Hermes 게이트웨이와 사용하지 않는 홈 자산을 **검증된 백업 뒤** 제거한다.
기본 설치와 스위치 없는 기존 노드는 보존한다. 릴리스 호스트
`~/.hermes/release-flags/peer-retired`의 내용이 개행 없는 정확한 `retired`일 때만
`peer-retired:retired` 표면이 승인 해시에 들어간다. 같은 배포 HEAD의 승인이 없으면
`PEER-RETIRED-UNAUTHORIZED`로 거부한다.

- Q238, 2026-10-18 19:39 KST: "지금 바로 다음 카드로"

이번 구현은 비루트 제거다. 메모리 시드·큐레이터/이동 타이머 은퇴는 별도 변경이며
이 코드가 USER.md·MEMORY.md를 삭제하거나 omo 메모리를 직접 고치지 않는다.
RAG·recall과 governed 스킬 마운트는 계속 쓴다.

## 사용과 백업·복원

형이 다음 릴리스 카드를 승인하면 기존 배포 경로가 agent·peer 각각의 계정으로
정지 잡 목록과 원본을 내보내고 백업 tar의 모든 파일·심링크를 다시 읽어 검증한다.
개수(30/3)·paused 상태·원본 잡 ID가 다르면 삭제하지 않는다.
모든 단계는 실패하면 멈추며 재실행은 기존 백업을 덮지 않는다.

계정별 기본 백업 위치는 `$HOME/.hermes/retired/p5/<승인 HEAD>/`다(디렉터리 0700,
tar·잡 내보내기 0600). `home.tar`, `inventory.json`, `jobs.json`, `cron-list.txt`,
`job-ids.json`, `exports.json`을 보존한다.

| 삭제 대상 | 백업과 되돌리기 |
|---|---|
| agent·peer 사용자 gateway 유닛과 drop-in | 각 계정 `home.tar`에서 원래 홈으로 복원 → 사용자 `daemon-reload` → 필요한 경우 유닛 enable/start |
| agent 홈 plugins·번들 skills·gateway import/runtime·skill-generation·자가 스킬 감사와 타이머 | agent `home.tar` 복원. 이후 원래 선언을 쓰는 복구 릴리스로 수렴 |
| agent `SOUL.md`와 그 백업·`config.yaml.bak*` | agent `home.tar`의 해당 파일만 복원. 현재 `config.yaml`은 손대지 않음 |
| 정지 Hermes 잡 33개 | 각 계정 `jobs.json`을 `.hermes/cron/jobs.json`에 복원. systemd 타이머와 동시 실행하지 않도록 paused 상태 유지 |

복원 명령은 해당 계정으로 `tar -xpf <백업>/home.tar -C "$HOME"`이다.
현재 CLI `~/.local/bin/hermes`, `~/.hermes/config.yaml`, 로그인·auth,
`~/.hermes/kanban.db`는 삭제 대상에 들어가지 않는다. `hermes-dashboard`는 별도 변경이다.
스위치를 지우기만 해서는 삭제 파일·잡이 돌아오지 않는다. 먼저 백업을 복원하고
복구 릴리스에서 은퇴 표식·스위치를 해제한다.

## 공급망과 관측

은퇴 표식이 있는 agent의 스킬 배포는 peer 증명 단계를 생략하지만 SANDBOX·REVIEW·
owner 승인·최종 digest/승인 재확인·마운트는 유지한다. 샌드박스는 agent 계정에서
임시 HOME과 가짜 자격증명으로 실행한다. 기존 peer/agent OS 계정 격리는 더 이상
제공하지 않는다. 스위치 없는 설치의 서명 모드와 attestation 계약은 그대로다.

은퇴 모드의 전량 판정은 peer 및 Hermes 전용 선언을 재배포하지 않는다.
정적 레거시 선언을 지우지 않으므로 다른 설치자는 영향받지 않는다.
영수증 `hermes_gateways=retired`, `peer_retired=retired`와 비루트 완료 표식이
은퇴 모드를 기록한다. 헬스체크는 gateway·peer·자가 스킬 루트 프로브를 퇴역(기대)로 본다.
doctor의 peer 계정 순회·gateway·메모리 관련 항목 정리는 형제 변경이 맡는다.

## 루트 단계는 별도

`bash docs/guide/p5-root-block.sh --dry-run`은 모든 단계를 미리 보여 주고 읽기 전용 SSH만
시험한다. 인자 없이 실행하면 워크스테이션 `~/.hermes/node.toml`의 SSH 별칭을 읽고
미리보기 → `yes` → 원격 sudo 암호 순서로 실행한다. 새 헬퍼·sudoers 권한은 설치하지 않는다.

peer 홈은 노드 `private_root/retired/peer-<UTC>-<PID>/home.tar`(root 0600)에 백업하고
크기·목록 개수·내용·SHA-256을 확인한다. linger 해제·계정 삭제·attestation 공개키와
peer-read sudoers 제거·peers.yaml의 peer 항목 제거는 각각 재조회한다.
`userdel -r`은 **HARD TO UNDO**다. 원 UID/GID·보조 그룹을 확인해 useradd 후 홈 tar를
복원하는 것은 best-effort이며, 설정 파일은 같은 백업의 사본으로 복원한다.
봇 토큰 폐기는 Discord 포털의 별도 소유자 작업이다.

관련: `automation/{peer_retired,p5_remove,p5_backup}.py`, `automation/deploy_all.sh`,
`automation/skill_gate.py`, `tests/unit/test_p5_*.py`.

## 점검(doctor)

- 계정 홈에 퇴역 표식이 있으면 사라진 Hermes 게이트웨이와 빈 Hermes 잡 목록을 정상(P5 퇴역)으로 본다. 표식이 없으면 멈춘 게이트웨이는 그대로 고장이다.
- 운영자 모드는 노드 비공개 루트의 `peer-retired` 표식이 있으면 peer 계정을 점검하지 않고 model-parity 비교를 생략한다.
