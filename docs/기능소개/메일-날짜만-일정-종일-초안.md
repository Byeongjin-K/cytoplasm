# 메일의 날짜만 있는 일정을 종일 일정 초안으로

아침 메일 다이제스트가 '날짜는 있고 시각은 없는' 일정(연차평가일, 서류 제출 마감 등)도
종일(all-day) 일정 초안 카드로 올린다. 노드 운영자가 릴리스 스위치로 켜며, 기본값은 지금과 같다
(날짜와 시각이 둘 다 있어야 초안).

## 왜

분류 프롬프트(`triage-classify-v1.md`)는 날짜와 시각이 본문에 둘 다 있을 때만 일정 문장을 돌려주고,
캘린더는 시각 없는 문장을 되묻기(exit 5)로 돌려보낸다. 그래서 평가일·마감일 메일은 다이제스트에
`🗓️ 일정 예정 · 날짜 미정` 줄만 남고 승인 카드가 없었다. 소유자 결정(2026-10-23, Q334):
"응, 종일 일정 초안으로 (카드가 조금 늘어남)". 초안을 만드는 시각은 그대로 아침 8시 다이제스트
한 번이다(Q333).

## 켜고 끄기

릴리스 호스트의 운영자 계정에서 줄바꿈 없이 `on`만 쓴다. 다른 값·공백·빈 파일은 거부한다(exit 4).

```bash
mkdir -p ~/.hermes/release-flags
printf %s on > ~/.hermes/release-flags/mail-schedule-all-day
chmod 600 ~/.hermes/release-flags/mail-schedule-all-day
```

기존 [릴리스 절차](../guide/manual-maintainer.md)를 따른다. 릴리스 카드에
`메일 다이제스트: 날짜만 있고 시각이 없는 일정(평가일·제출 마감)도 종일 일정 초안 카드로`가
표시되고 `mail-schedule-all-day:on` 표면과 HEAD가 승인에 묶인다. 승인 뒤 선언된 `push_file`이
노드 `~/.hermes/mail-schedule-all-day.mode`(0600)에 `on`을 쓰고 다시 읽어 확인한다.
다른 HEAD의 승인으로는 켤 수 없다.

파일을 지우고 다음 승인 릴리스를 하면 `off`가 배포되어 예전 동작으로 돌아간다. 표식이 없거나
`off`이면 분류 프롬프트는 바이트 그대로고, 캘린더는 시각 없는 문장을 예전처럼 되묻는다.
노드 표식이 깨졌으면 메일 쪽은 `MAIL-SCHEDULE-ALL-DAY-MARKER-INVALID`를 남기고 꺼진 것으로 다룬다
(다이제스트는 멈추지 않는다).

## 사용 시나리오

1. "가상 과제 연차평가 일정 안내 — 11월 18일 연차평가" 같은 메일이 온다.
2. 다음 날 08:00 다이제스트에서 분류기가 `schedule_text = "11월 18일 연차평가"`를 돌려준다
   (켜짐일 때만, 시각을 지어내지 않는다는 규칙과 함께).
3. 메일 쪽이 캘린더에 `CALENDAR_ALL_DAY_UNDATED=1`을 넘기고, 캘린더는 노드 표식도 `on`인지
   다시 확인한 뒤 종일 초안을 만든다. Google 명령은 `start.date=11-18`, `end.date=11-19`
   (Google 규칙대로 끝 날짜는 다음 날, 제외)이고 기본색 스위치가 켜져 있으면 색도 함께 동결된다.
4. 다이제스트 메일 카드에는 `🗓️ 일정 초안 → [승인 카드] · 11/18(화) 종일 연차평가`가 보이고,
   그 아래 답글로 승인 카드가 붙는다. ✅면 종일 일정이 생긴다.

여러 날이면 `12월 22일~23일 겨울학교` → `12/22(월)–12/23(화) 종일`. 시각이 있는 일정,
날짜가 없거나 모호한 일정(`11월쯤`), 끝 날이 시작보다 빠른 범위, 이미 지난 날짜는 예전과 같다
(되묻기 또는 거부 → `날짜 미정` 줄).

소유자 Discord 지시("11월 18일 연차평가 잡아줘")는 이 스위치와 상관없이 지금처럼 시각을 되묻는다.
환경 변수는 메일 다이제스트만 넘긴다.

## 알아둘 점

- 승인 카드(v4·v5)는 새 종일 일정의 `시작`·`종료`를 사람이 보는 첫·마지막 날로 보여 준다
  (`시작: 11-18 (종일)` / `종료: 11-18 (종일)`; Google 저장값의 끝은 다음 날, 소유자 Q336). 바뀌는 것은
  날짜형 생성 카드뿐이고, 시각 있는 카드·수정·삭제 카드는 바이트 그대로다. 이 변경 전에는 날짜형 생성 초안을
  만드는 경로가 없었으므로 저장된 카드도 바뀌지 않는다.
- 같은 날 비슷한 일정 확인(Q62, PR #163)은 종일 초안을 그날 00:00~24:00 구간으로 보고 시각 있는 기존
  일정과 비교한다. 이미 있는 종일 일정끼리의 비교는 #163 의 범위 밖이다.
