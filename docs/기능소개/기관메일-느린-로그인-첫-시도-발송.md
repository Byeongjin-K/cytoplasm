# 기관메일 로그인이 느려도 첫 시도에 나간다

## 무엇을
기관메일(mailon.kr) 로그인 화면이 늦게 뜨거나 잠시 응답하지 않아도, 승인된 메일이 10분 뒤 재시도를 기다리지 않고 첫 시도에서 나간다.

## 왜
2026-10-19 10:47 KST, 형이 ✅ 한 감사 답장이 첫 시도에서 실패하고 10분 뒤 재시도에서야 나갔다. 원인은 로그인 화면이었다. 페이지가 늦게 떠 아이디 칸을 채우는 명령이 브라우저의 30초 한도에 걸렸다. 로그인 만료도 브라우저 고장도 아니었다.

10월 노드 로그(로그인 178회) 실측:
- 페이지 열기: 보통 5초, 느릴 때 27초, 최장 58초.
- 그동안 기다리던 '페이지 load' 판정: 매번 25초 한도를 채우고 끝났다. 입력 칸이 실제로 쓸 수 있는지는 알려 주지 못했다.

형 지시(11:02 KST): "이 문제 해결하라고 짱도리에게 해".

## 어떻게 동작하나
- 아이디·비밀번호·OTP 세 칸이 실제로 화면에 생길 때까지 최대 90초 기다린다. 페이지가 바빠 확인 명령이 시간 초과되면 아직 준비 안 된 것으로 보고 1초 뒤 다시 본다.
- 칸 채우기가 시간 초과되면 5초 쉬고 화면을 다시 확인한다. 그다음 새 OTP 로 처음부터 다시 채운다. 이 재시도는 한 시도 안에서 두 번까지다.
- 이 재시도는 모두 로그인 제출 전 단계다. 발송 뒤의 재시도는 지금처럼 보낸편지함 중복 검사를 거친 뒤에만 한다. 그래서 같은 메일이 두 번 나가지 않는다.
- 시간 초과가 아닌 오류(칸 없음 등)는 다시 해 보지 않고 바로 실패한다. 90초 안에 화면이 끝내 준비되지 않아도 실패한다. 실패한 메일은 기존의 초안별 재시도(10·20·40·80·160분)를 탄다.

## 사용 시나리오
- 형이 회신 카드에 ✅ → 로그인 화면이 40초 늦게 뜸 → 칸이 생길 때까지 기다렸다 채우고 제출 → 메일이 그 틱에 나간다. 승인 스레드에는 평소의 발송 결과만 남는다.
- 기관메일 서버가 몇 분 동안 응답하지 않음 → 90초 뒤 그 시도는 실패로 끝난다. 스레드의 「⚠️ 발송 실패」 안내와 기존 재시도가 이어받는다.
