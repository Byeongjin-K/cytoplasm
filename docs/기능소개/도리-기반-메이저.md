# 도리 기반 메이저 — 기본 설치와 기존 노드 보존

## 무엇을·왜

새 설치의 기본값을 도리로 바꾼다. 공개 진입점·마법사·quickstart에서 리드+YooDori를
기본 구성으로 준비하고 옥돌·무돌·공돌만 선택한다. 별도 도리 선택을 놓쳐 Hermes 노드
설치로 들어가던 혼동을 없앤다. 포크 커밋은 계속 `dori/pin.toml` 하나가 정한다.

## 사용 시나리오

- 새 사용자가 `python3 -m automation.install --dry-run`을 실행하면 도리 포크·CLI·
  config·역할 계획만 나온다. 실제 설치는 git·Bun으로 고정 포크를 받고 기본 역할을 쓴다.
  Hermes·cron·게이트웨이·플러그인은 설치하지 않는다.
- 이미 자기 지침을 고쳤다면 재설치가 그 파일을 덮지 않고 차이만 보여 준다.
  운영 중 포크가 다른 커밋이면 `DORI-PIN-SRC-DIFFERS`로 멈춘다.
- 기존 노드 유지보수는 `--profile core|rag|report-hub|full`을 명시해야 한다.
  도리 기본 경로에 레거시 전용 옵션을 섞으면 거부하며 조용히 무시하지 않는다.
- 이미 도리로 전환한 노드는 설치기를 재실행하지 않고 서명 릴리스로 업데이트한다.
  기존 정지 스위치·타이머·자격증명·일시정지 잡을 유지한다. P5 제거는 별도 결정이다.

## 기본 경로에서 빠지는 Hermes 경로

| 경로 | 빠지는 이유 / 기존 노드 처리 |
|---|---|
| `install/installer.py`·`assets.py`·`plan.py`의 Hermes 전제·peer 계정·키 | 도리 기본 설치는 사용자 계정의 포크·역할만 준비한다. 레거시 선택에서는 보존 |
| `assets.py`의 `30-command-sync.conf` | Hermes gateway에만 필요한 drop-in |
| `deploy_cron.sh`·`converge_cron` | 기본 도리 설치는 Hermes 잡을 등록하지 않음. 기존 잡 삭제도 안 함 |
| `interop/deploy.sh`의 Hermes 플러그인·import farm·gateway drop-in | 기존 노드 전용 배포 경로로 남음. 도리 설치기는 호출하지 않음 |
| `memory_provider/deploy.sh`·Hermes 메모리 config 수렴 | Hermes 제공자 로더 전용. 새 도리 설치와 분리 |
| `hermes_compat/` 패치 | Hermes 내부 호환용이므로 도리 기본 설치에서 실행하지 않음 |

위 표는 **기본 설치 호출 경로에서 제외**한 목록이지 파일·설치된 데이터의 물리적 삭제
목록이 아니다. 새 도리 설치는 업무 금고·RAG 서버를 프로비저닝하거나 로그인·봇 기동을
대행하지 않는다. 기존 노드의 업무 런타임까지 제거하는 변경과 혼동하지 않는다.

## 별도 P5 단계와 복구

소유자 결정 **“멈춘 Hermes 잡 33개 지울지”**는 미결이며 기본값은 보존이다.
peer 계정·유닛·잡·봇·attestation 삭제는 이 카드에 포함하지 않는다.
복구는 직전 서명 릴리스의 내용을 더 높은 버전으로 재출시한다. 옛 태그 직접 설치는
롤백 방지 floor가 거부한다.
