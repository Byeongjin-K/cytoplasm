# 형이 끈 정기 작업을 릴리스 뒤에도 유지

릴리스 호스트의 `~/.hermes/release-flags/owner-timers-off`에 적은 작업은
같은 HEAD의 릴리스 승인 뒤에도 꺼진 채 유지한다. 종전에는 메모리 타이머 둘만
정지를 보존해, 예산·첨부 보관 같은 작업을 꺼도 전량 반영이 다시 켰다.

## 사용 예

릴리스 전에 파일을 아래처럼 준비한다. **agent의 `runner=systemd` cron 선언에
있는 이름만**, 이름순·중복 없이 한 줄에 하나씩 적고 마지막 줄도 LF로 끝낸다.
빈 파일·공백·CRLF·미등록 이름은 종료 코드 4로 거부한다. 파일이 없으면 기존 동작이다.

```text
budget-watch
mail-attachment-drive-watch
```

리허설(`automation/deploy_all.sh --rehearse`)은 목록과 노드 상태를 읽기만 한다.
릴리스 카드는 `형이 끈 정기 작업 유지: …` 한 줄로 알리고, 작업별 승인 표면이
목록 전체 바이트의 해시를 묶는다. 다른 HEAD·바뀐 목록·승인 없는 적용은 거부한다.

승인된 전량 반영은 agent 소유 `~/.hermes/owner-timers/off`(0600)를 원자적으로
배치하고 해당 타이머를 disable·stop한다. 점검은 실제 `disabled`·`inactive`를
확인하며, 일치하면 계획에 그 작업의 배포기를 반복해서 넣지 않는다.
doctor도 검증된 정지만 `released-off`로 표시하고 다시 켜진 상태는 고장으로 본다.
잡·유닛·데이터는 삭제하지 않는다.

**되돌리기:** 호스트의 `owner-timers-off` 파일을 지우고 새 릴리스를 승인하면 노드
표식을 제거하고 이전 목록의 타이머를 다시 켠다. 일부만 복구하려면 그 이름만 빼고
나머지 목록으로 새 릴리스를 승인한다. 별도 메모리 정지 스위치는 계속 우선한다.

관련: `automation/owner_timers.py`, `automation/owner_timers/deploy-manifest.txt`,
`automation/cron_timer.py`, `automation/release_approval.py`,
[소비 노드 갱신 가이드](../guide/소비-노드-갱신.md).
