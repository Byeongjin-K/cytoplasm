# 프로젝트 대시보드 — 호스트를 옮겨도 할 일 체크 저장

## 무엇을

테일넷으로 연 대시보드에서 할 일을 체크하면, 대시보드가 다른 테일넷 호스트로 옮겨 설정의 허용 주소가 옛 주소로 남아 있어도 저장된다. 열어 둔 화면은 저장이 권한 오류로 막히면 스스로 화면을 다시 받아 한 번 더 보낸다.

## 왜

2026-10-21 대시보드를 새 호스트로 옮긴 뒤 설정 `dashboard.tailnet.origins` 에 옛 주소만 남아, 휴대폰에서 연 화면의 체크가 모두 403(「권한이 없어 저장하지 못했습니다. 대시보드를 다시 열어 주세요.」)으로 막혔다. 새로 고쳐도 같았다. 서버 재시작이나 토큰 변경이 원인이 아니었다(토큰 파일 그대로, 재시작은 새 릴리스 감지·1시간 상한의 정상 종료).

## 사용 시나리오

- 형이 휴대폰에서 `https://<호스트>.<tailnet>.ts.net:<port>/` 를 열어 둔 채 할 일을 체크한다 → 서버는 그 요청의 `Origin` 이 브라우저가 연 주소 자신(`https://` + `Host`)이고 테일스케일 로그인이 허용 목록에 있으므로 저장한다 → 줄이 완료로 바뀐다.
- 서버가 그 사이 재시작돼도 → 같은 토큰을 다시 읽으므로 열어 둔 화면의 체크가 그대로 저장된다.
- 거부: 형 브라우저에 열린 다른 사이트가 serve 를 거쳐 체크를 보내면(다른 `Origin`) 403, 허용 목록에 없는 로그인이면 403, 테일넷 신원 없이 토큰 없이 보내면 401 — 인증은 약해지지 않았다.

## 관련

- 코드: `automation/project_board/server.py`(`_same_origin`, `do_POST`), `automation/project_board/dashboard.py`(저장 뒤 401·403 이면 화면을 다시 받아 한 번 재시도)
- 시험: `tests/unit/test_project_board_moved_host.py`
- 규약: [프로젝트 대시보드 가이드](../guide/프로젝트-대시보드.md) 「테일넷에서 열기」
- 승인 게이트 관여 없음(형 계정 안의 할 일 진행 기록).
