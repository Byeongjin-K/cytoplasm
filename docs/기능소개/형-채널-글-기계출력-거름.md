# 형 채널 글에서 기계 출력 거르기

## 무엇을

형 채널(#yoodori)에 자동으로 올라가는 글에서 JSON 덩어리·종료코드·ref·provider·경로·대문자 표식 코드·UTC 시각을
뺀다. 판정은 `automation/interop/owner_text.py` 하나이고, 정기 작업 출구(`cron_timer_run.deliver`)와 형 알림 출구
(`owner_notice.notify_owner`)가 그 판정을 거쳐 형 몫만 보낸다. 회의록 야간 작업은 사람 말 한 줄과 링크로 바꿨다.

## 왜

형 지시(2026-10-20 00:10 KST):
> 이렇게 메세지 남기는거 없애라고 짱도리에게 맡겨. 모든 메세지 생성 규칙 점검해서, ui 개선을 해서 직관적으로 만들어.

가리킨 글은 회의록 야간 작업 결과였다. 맨 위에 자식 CLI 의 결과 JSON(`exit`·`ref`·`provider`·화자 원값)이
그대로 붙고, 아래에 "미처리 전사본 1건 중 1건을 회의록으로 만들었습니다. - <전사본 파일명>" 이 이어졌다.
원인은 야간 작업이 자식의 stdout 을 잡지 않아 그 JSON 이 작업 stdout(= 형 채널 글)에 섞인 것이다.

## 사용 시나리오

- 회의록: 밤 12시에 미처리 전사본 하나를 회의록으로 만들면 형 채널에
  `회의록 하나 만들었어 — 10/19 stt-56` 과 Drive 링크만 올라간다. 결과 JSON 은 내부 로그에만 남는다.
- 정기 작업 경고: 다이제스트가 한 번 실패했다 회복되면 `DIGEST-FAIL stage=… code=…` 같은 줄은 형 채널이 아니라
  페어 채널(#dori-pair)로 간다. 같은 출력의 사람 말 줄(예: 새 메일 알림)은 형 채널로 그대로 간다.
- 형 알림: 경고 코드가 든 통지(예: 자가 스킬 이름 가림, 릴리스 런타임 어긋남)는 형 할 일이 아니므로 통째로
  페어 채널로 간다. 봉투를 줄 단위로 자르지 않는다.
- 실패 경로: 페어 채널이 설정되지 않은 설치는 JSON 만 빼고 지금처럼 원래 목적지로 보낸다 — 경고를 숨겨서
  없애지 않는다. 판정 규칙에 걸려도 출력 전체는 `~/.hermes/cron-timers/output/<작업>/` 에 남는다.
