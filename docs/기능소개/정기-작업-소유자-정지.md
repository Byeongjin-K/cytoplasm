# 소유자가 끈 정기 작업 보존

## 무엇을

소유자가 멈춘 정기 작업을 릴리스마다 다시 켜지 않도록, 잡별 정지 목록을
기존 릴리스 승인에 묶는다. 수렴·전량 배포 프로브·doctor가 같은 표식을 읽는다.

## 왜

기존에는 메모리 타이머의 정지만 보존했다. 다른 타이머를 수동으로 끄면
배포기가 다시 켜고, 전량 판정도 계속 그 배포기를 할 일로 표시했다.

## 설정과 사용 시나리오

릴리스 호스트의 `~/.hermes/release-flags/cron-timers-off`에 아래처럼 쓴다.
각 줄은 ASCII 잡 이름 하나이며 **마지막 줄도 LF 개행으로 끝낸다**.
이름은 `[a-z0-9][a-z0-9-]{0,63}`, 사전순 정렬·중복 없음이 필수다.
빈 파일·빈 줄·공백·CRLF·현재 선언에 없는 이름은 거부한다.

```text
budget-watch
mail-attachment-drive-watch
```

- 릴리스 카드는 선택한 잡별 정지를 표시한다.
  `cron-timer:<name>:off`와 정확한 `off`의 SHA-256이 승인 해시에 들어간다.
  같은 HEAD의 소유자 승인 없이는 어느 잡도 정지하지 않는다.
- 승인 뒤 `deploy_all.sh --apply`가 agent 타이머를 disable·stop하고
  `~/.hermes/cron-timers/owner-off.mode`에 같은 목록을 0600으로 원자 배치한다.
  그 뒤 잡 배포기는 `CRON-TIMER-UNCHANGED ... released-off`를 출력한다.
  이 경로는 Hermes 잡 목록이나 스크립트 배포본을 요구하지 않는다.
- 예: 첨부 업로드 감시를 위 목록으로 정지 → 다음 릴리스에도 타이머는
  disabled·inactive이며 전량 프로브는 일치, doctor는 `released-off`다.
  누가 타이머를 다시 켜면 프로브·doctor가 `released-off-drift`를 표시한다.
- 파일을 지우거나 목록에서 잡을 뺀 뒤 재배포하면 표식에서 빠진 잡은
  기존 Hermes 일시정지 확인을 거쳐 일반 타이머 수렴으로 돌아온다.
  미설정 설치는 기존 동작 그대로다.
- 메모리 두 잡은 이 목록에서 거부한다. 기존 `hermes-memory-off`와
  미결 메모리 선택 게이트를 그대로 사용한다.
