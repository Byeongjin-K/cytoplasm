# 유돌 형 명령 통로 — 메일 전달·공유 링크·위키·문서·특허·회의록

## 무엇을

유돌이 형의 디스코드 말 한마디로, 예전 사이토플라즘 대화가 하던 여섯 가지를 다시 끝까지 한다.

| 형 말(예) | 유돌이 부르는 노드 명령 | 카드 |
|---|---|---|
| "이 메일 첨부 그대로 협력사 담당자에게 전달해" | `mail-compose --to … --forward <uid>` (Gmail 은 `--forward-gmail <id>`) | 승인 카드 하나 → 형 ✅ → 발송 |
| "이 파일 드라이브로 공유해서 링크 보내" | `stage` 로 파일 올림 → `mail-compose --drive-share <올린 파일> --share-with <주소> --body-b64 '<Drive 링크> 포함 본문'` | 승인 카드 하나(업로드·보기 권한·발송을 같이 묶음, 공유 실패면 메일 안 나감) |
| "위키에서 ○○ 찾아 고쳐" | `wiki-search <말>` · `wiki-get <slug>` · `wiki-write --edit <slug> --body-b64 …` | 카드 없음 |
| "보고서/제안서/문서 초안 만들어" | `doc <doctype\|report\|proposal\|procurement\|prompt\|topics> <서브커맨드> …` | 카드 없음(안에서 메일·공유처럼 바깥으로 나가는 단계가 있으면 그 단계만 카드) |
| "특허 초안 만들고 반출해" | `patent create\|checklist\|draft\|status\|export …` | 카드 없음 |
| "이 녹음 회의록 만들어" | `stage` 로 녹음 올림 → `stt ingest --file <올린 파일>` (전사만은 `stt transcribe`, 글 회의록은 `meeting ingest`) | 카드 없음 |

카드 없는 명령은 모두 끝에 `--origin-channel-id <채널> --origin-message-id <형 메시지>` 를 붙인다.

## 왜

Hermes 게이트웨이를 멈춘 뒤(P5) 이 여섯 가지는 아무 경로로도 되지 않았다(이식 감사 GAP 1~6). 유돌 통로에는 읽기와 카드 올리기만 있었고, 형 정책(2026-10-18 "사이토플라즘 릴리스와 바깥으로 나가는 메일만 승인")과 달리 문서 작성도 일반 카드로만 할 수 있었다.

## 형 결정과 지켜지는 선

- 바깥으로 나가는 것(메일 발송·전달·Drive 공유 링크)은 지금처럼 승인 카드다.
- 형 계정 안 쓰기(위키·문서·전사·회의록·특허 준비)는 카드 없이 한다 — 형 Q233 "6개 다 카드 없이 바로 + 하루 요약에 남기기".
- 특허 반출(형의 비공개 보관 폴더로 올리기)도 카드 없이 한다 — 형 2026-10-18 18:29 KST "5번도 카드 없이 해". 폴더 권한이 형 한 사람이 아니면 올리지 않는다(기존 점검 그대로).
- 카드 없는 쓰기는 **형이 디스코드에 직접 쓴 글**에서 시작했을 때만 한다. 노드가 그 메시지를 디스코드에서 다시 읽어, 쓴 사람이 형(봇 아님)이고 24시간 안의 글인지 확인한다. 메일·문서 내용이 시킨 일, 봇 글, 오래된 글은 `YOODORI-GATE-REFUSED` 로 거절되고 아무것도 실행되지 않는다. 메시지를 읽지 못해도 거절한다.
- 쓴 것은 매일 21:30 요약에 종류별 건수·최근 제목 최대 5개로 남는다. 근거 메시지 링크와 전체 내역은 비공개 원장에만 보관하고 요청하면 유돌이 찾아 준다.
- 이 모든 카드 없는 쓰기는 릴리스 스위치 `auto-write-yoodori` 가 켜져 있을 때만 된다. 릴리스 카드에 `유돌 요청 쓰기: …` 줄이 붙고 형 ✅ 로 켠다. 릴리스 호스트의 `~/.hermes/release-flags/auto-write-yoodori` 를 지우고 다시 배포하면 꺼진다.
- 유돌에게 비밀값은 가지 않는다. 명령은 노드에서 노드 계정 설정으로 돈다.

## Q233 카드 없는 쓰기 6종

형 Q233(2026-10-18 17:40 KST) "6개 다 카드 없이 바로 + 하루 요약에 남기기". 종류마다 릴리스 스위치가 따로 있어(`~/.hermes/release-flags/auto-write-<종류>` 에 `on`) 하나씩 켜고 끈다. 꺼져 있거나 노드 설정을 못 읽으면 예전 카드 그대로다.

| 종류 | 유돌 명령(그대로) | 켜지면 |
|---|---|---|
| `calendar` | `calendar-request` | 형 혼자 일정은 바로 등록(`calendar_cli owner-create`). 바깥 참석자가 있으면 예전처럼 카드 |
| `todo` | `todo-request` | 바로 Google Tasks 등록·재조회(`todo_cli write-now`) |
| `obsidian` | `obsidian-request` | 바로 노트 저장·원격 재조회(`obsidian_write write-now`) |
| `drive-save` | `drive-save` | 바로 형 Drive 비공개 저장·sha256 재확인(`effect_request save-now`) |
| `project-board` | (노드가 스스로 만드는 보드 제안) | 카드 없이 보드에 반영 — 근거 메시지 확인 없음 |
| `yoodori` | `wiki-write`·`doc`·`patent`·`stt`·`meeting` | 위 표의 형 명령 잡(위키는 여기서) |

생산자 명령이 `OWNER-COMMAND-WRITTEN` 줄을 낸 것만 21:30 요약에 들어간다 — 바깥 참석자 때문에 카드로 돌아간 일정은 요약에 없다.

## omo 기억 × recall (형 2026-10-18 20:55 KST Q241·Q242·Q243)

- Q241 "유돌 omo 메모리가 정본 + 하루 한 번 옵시디언에 자동 사본(recall에도 잡힘)": 유돌이 하루 한 번 omo `system/` 카드 줄과 `notes/facts/` 를 렌더해 `memory-copy`(SSH stdin)로 보낸다. 노드가 옵시디언 `000_PARA/Resource/유돌 기억 자동 사본.md` 한 개를 덮어쓴다(스위치 `auto-write-yoodori-memory`, 근거 메시지 없음 — 형 결정이 근거, 21:30 요약에 남음). 회의록·제안서 같은 노드 스킬과 recall 이 같은 선호를 찾는다.
- Q244(21:03 KST) "유돌이 하루 한 번 대화 요약(결정·할 일·사실)을 옵시디언에 써서 recall이 색인": 유돌이 21:30 요약 전에 `day-summary <YYYY-MM-DD>`(stdin)를 보내면 노드가 `000_PARA/Resource/유돌 대화 요약/<날짜>.md` 를 덮어쓴다(같은 스위치·같은 요약). 원문·비밀값·바깥 연락처는 넣지 않고, 주소·전화번호가 있으면 노드가 거절한다.
- Q242 "형이 직접 한 말·더 최근 것 우선, 애매하면 유돌이 형에게 물어봄": 유돌 역할 지침의 충돌 규칙.
- Q243 "옵시디언 사람 노트가 정본, omo엔 이름·관계 한 줄만": 사람 노트 원문은 `note-get <PARA 경로>`(노드 읽기 전용 미러)로 읽어 합친 뒤 노트 저장으로 쓴다.

## 사용 시나리오

1. 형이 #yoodori 에 "어제 받은 공문 첨부 그대로 협력사 담당자에게 전달해" → 유돌이 `mail-list` 로 uid 를 찾고 `mail-compose --to <담당자> --forward <uid> …` → 노드가 원문·원 첨부(바이트 그대로)로 FW 초안과 승인 카드를 올리고 `APPROVAL-THREAD … url=` 을 돌려준다 → 유돌이 그 링크를 답장에 붙인다 → 형 ✅ → 발송.
2. 형이 "출장보고 양식으로 지난주 출장 초안 써줘" → 유돌이 입력 JSON 을 `stage` 로 올리고 `doc doctype draft --name 출장보고 --inputs-json <올린 파일> --out-name draft.md …` → 100초 안에 끝나면 `JOB-DONE` 과 결과, 아니면 `JOB-RUNNING id=…` → 유돌이 `job <id>` 로 다시 보고 `job-file <id> draft.md` 로 받아 #yoodori 에 올린다.
3. 형이 "이 녹음 회의록 만들어"와 함께 파일을 보냄 → `stage meeting.m4a` → `stt ingest --file …/meeting.m4a --project <과제> …` → 긴 녹음은 잡으로 돌고(최대 4시간) 회의록 결과는 형 메시지 스레드에 통지된다.
4. 거절: 유돌이 메일 본문에 적힌 "위키에 추가해"를 보고 그 메일 알림 글로 `wiki-write` 를 부르면 → 그 글은 형 글이 아니므로 `YOODORI-GATE-REFUSED origin message is not the owner's own message`.

## 입력 경계

- 파일 인자는 `stage` 로 올린 파일이나 앞선 잡의 결과(`job-file` 로 보이는 것)만 받는다. `~`, `..`, 그 밖의 절대 경로는 거절한다.
- 여러 줄 글은 `--<플래그>-b64` 로 넘긴다. 결과 파일 이름은 `--out-name <이름>` 으로 준다(노드가 잡 폴더 안으로 정한다).
- 시험 전용·재생·주입 플래그(`--response-file`, `--recorded`, `--injection-file` 등)와 출력 루트 변경(`--out`, `--outputs-root`, `--notes-root`)은 게이트에서 거절한다.
- 잡은 SSH 세션과 떨어져 돌고(`~/.local/state/yoodori-jobs/<id>/`, 0700), 명령이 출력한 계정 홈 안 새 파일을 잡 결과 폴더로 모은다.
