# 소유자 메시지 계약 — 어느 스레드인지 찾으러 다니지 않게

## 무엇을

계약을 채택한 승인·결과·정기 통지는 **대상 / 사실 / 위치 / 인계 / 되돌리기** 다섯 필드를 가진다.
새 승인 카드는 Discord용 `owner-ko-v2`로 **제목 → 항목별 사실 → 결정 버튼·기한** 순서로 읽는다.
취소하면 무엇이 달라지는지와 에이전트의 다음 실행도 함께 알린다. 이전 `owner-ko-v1`은 그대로 재생한다.

## 왜

에이전트가 스레드에 올렸다고만 하고 **어느 스레드인지 가리키지 않아 소유자가 직접 찾아야 했다**.
이제 다른 곳에서 받은 통지에도 원래 위치의 링크가 붙고, 좌표를 모르면 추측 링크 대신 검색 안내를 준다.
기존 승인 카드에서는 긴 식별자와 한 줄로 접힌 일정 정보가 결정을 가렸다. v2는 사실의 줄바꿈을
보존하고, 자기 메시지를 가리키는 중복 위치 줄을 빼며, 참조 키는 하단에 8자만 표시한다.
`owner-ko-v3`(2026-09-22)는 같은 배치에서 참조 키만 **자르지 않고 전부** 보인다 — 8자로 자르면
`of_00924`처럼 공통 접두어가 자리를 먹어, 완전한 값처럼 보이지만 대상을 가리키지 못했다.
Plaud 노트 카드 v7이 처음 채택했고(폴더 이동 `of_`를 뗀 정규 녹음 id), 저장된 v2 카드는 그대로 재생한다.

`owner-ko-v4`(2026-10-15)는 원문 바이트가 승인에 묶이는 짧은 메시지용 판본이다.
사실의 줄바꿈·줄 끝 공백까지 그대로 표시하고, 참조 키도 전부 싣는다. 메모리 줄별 제안은
이 판본으로 원문·목적지·세 리액션을 한 메시지에 담는다. 지역 완료 통지에 후속 조치·복구가 없으면
사실과 조치 없음만 한 줄로 표시한다. 비지역 위치와 실제 복구 조치는 생략하지 않는다.
봉투·검증 계약과 기존 v1/v2/v3 게시 바이트는 바뀌지 않으며, 기존 생산자의 판본도 강제로 올리지 않는다.

`owner-ko-v5`(2026-10-19)는 형 채널로 가는 정기 알림을 **한 줄**로 보인다: 사실 한 줄, 원본 링크가 있으면 ` · <링크>` 를 붙인다(미리보기 없음). 대상 키·검색 라벨·인계·되돌리기 줄은 봉투(기록)에만 남는다. 첫 채택은 일정·마일스톤 리마인더다 — 2026-10-19 12:25 KST 형 채널에 `대상: 리마인더 (<일정 id>|…) 사실: ⏰ …` 다섯 줄 원형이 그대로 보였다. 앞선 판본은 그대로다.

## 사용 시나리오

1. **정상·폴백**: `<요청 키>`의 결과를 승인 스레드에 보내려다 실패 → 기존 폴백 통지 경로로 배달하면서
   그 목적지에 맞춰 다시 렌더 → 서버·스레드·메시지 좌표가 있는 원 승인 메시지의 **클릭 가능한 링크**를
   소유자가 받아 바로 연다. 같은 스레드 안에서 읽을 때만 위치가 `여기`다(양쪽 채널 좌표가 실제로 같을 때).
2. **서버 미상**: 같은 요청의 서버 좌표가 없는 상태에서 스레드 밖으로 통지 → 링크를 만들지 않고
   생산자가 준 `<검색 라벨> / <요청 키>`를 표시 → 소유자는 그 키로 찾는다. `@me`로 짐작한 DM 링크는 없다.
   원래 위치가 해당 없거나 이 메시지 자체이면 URL 없이 표시하며, 외부 자료 주소는 같은 채널이어도 별개다.
3. **조치 없음**: 추가 조치·실행이 없는 완료 통지를 받음 → 인계에 둘 다 없다고 명시 → 답을 기다리는
   요청으로 오해하지 않는다. 승인 카드의 기한·취소 효과도 함께 읽되, 이미 누른 카드의 삭제·재게시로 바꾸지 않는다.
4. **일정 검토**: 일정 수정을 요청 → 새 캘린더 v4 카드에서 제목·시작·종료를 각각 읽고 변경/유지
   표시를 확인 → 결정 줄의 승인 또는 취소 리액션을 누른다. 시각은 `2030-01-02 09:00 (+09:00)`처럼
   보이며 종일 일정은 날짜만 표시한다. 전체 바인딩 해시는 카드 마지막 인라인 코드에 남는다.
5. **게시 거부**: 완성 카드가 기존 Discord 길이 한도를 넘거나 캘린더 상세를 해석할 수 없음 →
   내용을 잘라 승인시키지 않고 게시 전에 거부한다. 이미 게시된 v1/v2/v3 일정 카드는 바꾸지 않는다.

새 판본: 메일·예산·조율·특허·할 일·스킬 배포/발행·그룹 제출은 v3, 캘린더·수리는 v4,
릴리스는 v5, Plaud는 v6, 메모리 재배치는 v3이다. 승인 대상 해시·표면·리액션 판정은 바뀌지 않는다.
위키는 `wiki_gate.py` 수정 동결로 기존 카드 v2를 유지한다. 자체 카드 없는 Obsidian 위임은 별도
판본을 만들지 않는다. 결과·정기 통지 파사드는 명시적 v2를 지원하지만 기존 생산자의 v1 판본을
강제로 바꾸지 않는다(목적지에 맞춰 원 봉투를 렌더한다는 기존 호환 계약 유지).

모든 발신자가 봉투를 만드는 것은 아니다. **영구 구조 예외는 네 곳**이다: 자체 카드 없는 승인 위임,
최소정보 리마인더, 그리고 `origin_notice.deliver`가 폴백 목적지로 다시 렌더한 문자열을 받는
budget·calendar 콜백이다. 두 콜백은 기존 호환 문구도 받고, calendar는 워처·리마인더의 문자열도 받는다.
미이관 원장 `_RAW_CONTENT_EXEMPT`는 실제로 비어 있고 재등록을 막는 가드가 있으며, 네 예외는 별도
`_PERMANENT_RAW_CONTENT_EXEMPT`에 사유와 함께 남는다. 새 미이관 발신자를 영구 예외 옆에 숨기지 않기 위한 분리다.
파사드의 **`content: str` 경로는 유지**한다. 이 경계들과 구 런타임 호환이 남아 있고, 봉투를 import할 수 없는
회의 게이트웨이의 별도 접수 통지도 문자열을 쓴다. 문자열 전송을 없애 회의 통지를 끊는 변경이 아니다.
