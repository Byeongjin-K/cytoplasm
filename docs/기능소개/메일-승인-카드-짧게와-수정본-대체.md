# 메일 승인 카드 짧게 · 같은 스레드 수정본 대체

## 무엇을
메일 발송 승인 카드에 받는 사람·제목·본문·✅/⛔ 만 보이고, 형이 같은 스레드에서 고친 새 초안이 오면 옛 미결 카드는 「새 판으로 대체됨」으로 닫힌다. 형 요청이 이미 스레드 안이면 카드도 그 스레드에 선다.

## 왜
형 2026-10-19 00:00 KST: "한번 관련 스레드 열면 그 열린스레드에서 계속 처리하게 해. 이렇게 매번 새 스레드 열지말고." — 한 메일을 세 번 고치자 카드가 매번 새 스레드에 올라갔다. 같은 시각 카드 아래 `취소 시`·`다음`·`되돌리기`·`참조: <draft>`·sha256 줄을 가리켜 "이런 것도 짱도리에게 남기지 말고, 내부용으로만 쓰라고 해. 디스코드에서는 안보이게 해."

## 사용 시나리오
- 형이 #yoodori 스레드에서 "유 박사님께 점심 메일 보내줘" → 유돌이 `mail-compose` → 카드가 **그 스레드**에 받는 사람·제목·본문만으로 선다 → 형 ✅ → 발송, 결과도 같은 스레드.
- 형이 같은 스레드에서 "시간을 12시 반으로 고쳐" → 새 카드가 같은 스레드에 서고, 옛 카드는 「🔁 새 판으로 대체됨」으로 바뀐다. 옛 카드에 ✅ 해도 아무것도 나가지 않는다.
- 형이 이미 ✅/⛔ 한 옛 카드는 건드리지 않는다. 다이제스트 스레드(여러 메일 카드가 함께 있는 곳)의 카드는 대체하지 않는다 — 형 요청이 그 스레드에서 쓰인 새 메일만 대상.

## 어떻게 묶이나
카드 판본 4(`render_version="4"`)는 게시한 글 전체의 sha256 을 레코드 `card_sha256` 에 남기고, 확인할 때 디스코드 글이 정확히 그 글인지 본다(글이 바뀌면 거부). 옛 판본(1~3) 카드는 예전처럼 글 속 해시로 확인한다.
