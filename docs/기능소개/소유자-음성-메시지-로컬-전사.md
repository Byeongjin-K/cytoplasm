# 소유자 음성 메시지를 로컬에서 한국어로 전사해 친 글처럼 받는다

## 무엇을

소유자가 `#agent-chat`(스레드 포함)이나 DM 에 Discord 음성 메시지를 보내면, 게이트웨이가 그 음성을 노드의 로컬 whisper.cpp 로 한국어 전사한다. 에이전트는 그 전사문을 소유자가 직접 친 글처럼 받는다. 글 앞에는 감사용 표식 `[음성 메시지 · 로컬 전사]` 가 붙는다.

## 왜

2026-10-12 소유자 지시: "에이전트 챗 채널에서 내가 보이스로 보내면 로컬 전사 모델로 전사해서 한국어로 내가 하는 말을 텍스트로 쓴 것처럼 에이전트가 보게 해줘". Hermes 게이트웨이도 음성을 자동 전사하지만, 그 경로는 faster-whisper `base` 로 언어를 추정한다. 노드 실측에서 한국어 음성을 `lang=en` 으로 잡았다. 실패하면 같은 약한 모델로 다시 시도하므로, 결국 추측한 내용으로 행동하게 된다.

## 사용 시나리오

- **보통 경우**: 소유자가 `#agent-chat` 에 "내일 오후 세 시에 회의 일정 잡아 줘" 라고 말한 음성을 보낸다.
  - 에이전트가 받는 글: `[음성 메시지 · 로컬 전사] 내일 오후 3시에 회의 일정을 잡아줘.`
  - 에이전트는 타이핑한 요청과 똑같이 캘린더 승인 카드를 만든다. 일정은 소유자가 카드에 ✅ 를 눌러야 등록된다.
  - 3.7초 음성은 노드 GPU 에서 1초 남짓에 전사된다.
- **글과 함께 보냄**: 음성에 글을 덧붙이면 전사문 아래에 그 글이 그대로 붙는다.
- **전사 실패**: 무음, 모델 오류, 10분을 넘는 음성, 노드에 도구가 없는 경우다.
  - 그 메시지는 에이전트에게 가지 않는다.
  - 메시지가 온 자리(채널이면 그 메시지에 단 「음성 메시지」 스레드, 스레드·DM 이면 거기)에 "음성 메시지를 전사하지 못했습니다 — <사유> … 이 음성으로 실행된 것은 없습니다" 가 남는다.
  - 다시 보내거나 글로 적으면 된다.
- **다른 사람·봇의 오디오**: 이 경로는 건드리지 않는다. 이벤트는 예전 그대로 게이트웨이로 간다(허용되지 않은 사용자는 원래대로 버려진다). 첨부한 오디오 파일(m4a·mp3 녹음)도 대상이 아니다 — 긴 녹음은 speechtotext 전사본 경로다.

## 지키는 것

- **신원**: 봇이 아니고 작성자 id 가 interop `owner_id` 인 사람의 음성만 처리한다.
- **권한이 넓어지지 않음**: 전사문 앞에 표식이 붙으므로 `!pause-agents` 같은 kill-switch 명령이나 프로토콜 봉투로 읽히지 않는다. 승인은 여전히 카드의 ✅ 리액션뿐이다.
- **로컬 전용**: 원음은 노드 밖으로 나가지 않는다. 변환한 wav 는 작업 디렉터리째 지우고, 게이트웨이가 받아 둔 원본 음성 파일도 Hermes 오디오 캐시 안의 것만 지운다. 전사문은 로그에 남기지 않는다(`interop voice transcribed clips=… chars=… elapsed_ms=…`).
- **끄기**: 게이트웨이 env 에 `AUTOPHAGY_VOICE_TRANSCRIBE=0` 을 두면 예전 Hermes 기본 동작으로 돌아간다.

## 관련

- `automation/interop/voice_transcript.py` — 판정·전사·정리·실패 통지
- Hermes 플러그인의 음성 훅은 은퇴했다. `voice_transcript.py`의 변환 라이브러리와 테스트만 보존하며 새 게이트웨이 훅을 설치하지 않는다.
- 도구: speechtotext 스킬과 같은 `SPEECHTOTEXT_WHISPER_BIN`·`SPEECHTOTEXT_WHISPER_MODEL`. 게이트웨이 env 에 없으면 계정 `~/.env.secrets` 에서 읽는다.
- 시험: `tests/unit/test_voice_transcript.py`, `tests/unit/test_voice_transcript_integration.py`(합성 한국어 시료 `tests/fixtures/voice/`)
- 규약: [interop §3.6](../guide/interop-규약.md)
