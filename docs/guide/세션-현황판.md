# 세션 현황판 — 만드는 방식과 대시보드 통합 지침

> 2026-10-16 소유자 지시: "UI 만드는 방식 … 나중에 프로젝트 대시보드에 통합할 거라 … 만드는 지침 엠디를 일단 만들어
> 놓으라". 이 문서는 **지금 통합하지 않는다**. 나중에 "세션 현황판을 대시보드에 넣어" 라는 일을 맡은 세션이 이 한 장만
> 읽고 같은 보드를 다시 만들어 대시보드 탭으로 붙이게 하는 것이 목적이다.
>
> 근거는 그 보드를 만든 lane 의 실제 산출물(`board.html`·`report.json`·`qa/*.json`·데스크톱/모바일 캡처)과 그 lane 의
> 실행 기록(도구 호출)이다. 거기서 그대로 확인한 것만 평서문으로 쓰고, 확인하지 못한 판단은 **[추정]** 으로 표시한다.
> 산출물은 이 저장소 밖(그 lane 의 작업 폴더)에 있고 저장소에는 들어오지 않는다. 대신 그 보드를 만든 **생성기와
> 수집기**를 lane 기록에서 되살려 이 문서 옆 [`세션-현황판/`](세션-현황판/) 에 두었다(5.1, 원본과 비교한 결과 포함).

## 1. 무엇이고 누가 쓰나

- **무엇**: 한 호스트에서 지난 7일 동안 돈 모든 세션 — 작업 레인(사람이 맡긴 일 단위), 코딩 에이전트 세션, 사람 없이 도는
  감시·웹 서비스·예약 실행 — 을 조직도 모양 한 화면에 모은 **읽기 전용 현황판**이다. 결과물은 자체 완결 HTML 한 장과
  그것을 찍은 PNG 두 장(데스크톱·휴대폰 폭)이다.
- **보는 사람과 장면**: 연구원이 휴대폰에서 그림 한 장을 열어 "이번 주 에이전트가 무슨 일을 얼마나 했는지" 를 10초 안에
  훑는다(원 브리프의 장면). 그래서 맨 위에 큰 숫자 세 개, 그 아래 하루별 막대, 그 아래 갈래별 카드 순서다.
- **이 문서를 쓰는 사람**: 대시보드 통합을 맡은 다음 세션. 7장(통합)을 먼저 보고, 데이터·화면·QA 는 2~6장을 따른다.

## 2. 데이터 출처와 세는 법

모든 출처는 **메타데이터만 읽는다**. 대화 본문은 읽지 않는다(보드 꼬리말에도 그렇게 적혀 있다).

### 2.1 기간(7일 창)

- 시작 `W0` = 오늘 기준 7일 전 **0시 KST**(호스트 시계는 UTC 이므로 UTC 로는 전날 15:00), 끝 `NOW` = 만든 시각.
  원 보드는 `2026-10-09 00:00 KST ~ 2026-10-16 16:29 KST` 였다(`report.json` 의 `window`).
- 창 안에 **조금이라도 걸친** 것을 센다: 끝났으면 끝난 시각이 `W0` 이후, 아직 열려 있으면 무조건 포함.
- **걸린 시간은 창 안의 시간만** 센다: `(끝 또는 NOW) − max(시작, W0)`. 창 전에 시작해 이어진 것은 `carried` 로 표시해
  하루별 막대에서 뺀다(보드 문구: "기간 전에 시작해 이어진 레인 2건, 에이전트 세션 14개는 막대에서 뺐습니다").

### 2.2 작업 레인

- 출처: 메신저 에이전트(dori) 레지스트리의 레인 파일 `<dori 상태 폴더>/state/lanes/*.json`. 이 호스트에는 레지스트리가
  셋 있었고 그중 하나는 다른 하나의 사본이라 **레인 키로 중복을 없앴다**.
- 쓰는 칸: `key`, `status`, `openedAt`, `closedAt`(그리고 분류용 `key`). `title` 은 사람 이름이 섞여 있어 **화면에 내지 않는다**.
- 상태 대응: `closed`→완료, `done-claimed`→확인 대기, `open`→진행, `paused`→멈춤, `not-done`→미완, 그 밖→진행.
  (원 보드 기준이다. 대시보드 세션 탭은 2026-10-16 부터 `paused` 를 「대기」로 보이고, 작업 창이 멈췄거나 꺼진 레인만
  「막힘」이다 — 7.4.)
- 분류: 레인 키 앞머리에 맞춘 **손으로 쓴 정규식 표**로 6개 분야(에이전트 운영·업무 비서·메일·연구·실험·웹·대시보드·
  조사·문서·장비·인프라) 아래 주제(예: "지침·브리프", "메일 정리·전달", "GPU 관리")에 넣었다. 맞는 규칙이 없으면 "기타" 분야의
  "세션 N" 이다(원 보드에서는 0건). 그 표는 이 호스트의 레인 이름에 맞춘 것이라 그대로 옮길 수 없다(8장).
- 원 보드 수치: 177건(완료 170 · 진행 1 · 확인 대기 2 · 멈춤 3 · 미완 1).

### 2.3 코딩 에이전트 세션

- 출처: 원 보드는 `coding-agent-sessions` 스킬의 찾기 스크립트 `find-agent-sessions.py list --from <W0 전날> --include-subagents
  --limit 5000 --workers 32` 가 내는 목록(플랫폼·모델·`created_at`·`updated_at`·파일 경로)을 썼고, 첫·마지막 사용자 문장 칸은
  **받자마자 버렸다**. 10분마다 도는 수집기(`session_feed/collect.mjs`)는 같은 규칙(만든 시각 = 처음 시각, 갱신 = 마지막 시각,
  모델 = 처음 나온 모델 칸, 플랫폼+세션 id 하나에 세션 하나)으로 Claude Code(`~/.claude/projects` 등)와 Senpi(`~/.omo/agent/sessions` 등)
  JSONL 을 직접 읽되, **지난 실행이 멈춘 자리부터 새로 쓰인 줄만** 읽는다(기록은 뒤에 붙기만 하므로). 파일별로
  읽은 위치·시각·모델·응답 수는 비공개 캐시(`SB_CACHE`, 경로는 그 파일에만)에 남고, 창 시작 전에 마지막으로 쓰인 파일은 열지 않는다.
  같은 "지금"으로 돌린 찾기 스크립트 방식과 비교해 세션 1,851개의 행이 하나도 다르지 않았다(2026-10-16). 한 번 실행 비용은
  CPU 27초·메모리 최대 3.2GB 에서, 캐시가 있을 때 0.6초·37MB, 캐시 없이 처음 읽을 때 11초·165MB 가 됐다(systemd 측정).
- 창 판정: `updated_at`(없으면 `created_at`) ≥ `W0`. 서브에이전트 실행도 한 세션으로 센다.
- 걸린 시간: `updated_at − max(created_at, W0)`. **진행 중**: `NOW − updated_at < 15분`.
- 응답 수: 세션 파일에서 `"type":"assistant"`(Claude Code) 또는 `"role":"assistant"`(Senpi) 가 든 **줄 수**를 센다
  (원 보드는 `grep -c`, 수집기는 새 줄만 세어 더한다) — 본문을 파싱하지 않기 위해서다. **[추정]** 한 응답이 여러 줄로 기록되는 형식이면 실제 모델 호출 수보다 크다.
- 묶음: 플랫폼(클로드 코드 / 센피) 아래 모델 계열(Opus 5.5·Sonnet 5.5·Fable 5.1·Haiku·기타 모델, 모델 이름 정규식).
  기록이 없는 플랫폼(Codex·OpenCode 등)은 **"없음" 칸**으로 남긴다.
- 상주 작업 창: `tmux ls` 의 `aoe_` 로 시작하는 세션을 이름으로 리드 창 / 레인 작업 창 / 프로젝트 창으로 나눈다(생성 시각만 씀).
- 원 보드 수치: 1,806개(클로드 코드 1,574 · 센피 232), 상주 창 14개. 누적 시간은 **동시에 돈 시간을 모두 더한 값**이다.

### 2.4 감시·서비스

- 출처: `systemctl --user show <유닛> -p ActiveState,SubState,ActiveEnterTimestamp,NRestarts`, 그리고
  `journalctl --user -u <유닛> --since <W0>` 에서 `Started` 줄 수(=7일간 시작 횟수), 예약 유닛은 `Finished` 줄 수(=실행 횟수)와
  `Failed with result` 줄 수(=실패 횟수).
- 원 보드의 16종 목록은 **손으로 만든 표**였다: lane 이 위 명령 출력을 읽고 유닛마다 일반 라벨("디스코드 수신", "레인 감시",
  "릴리스 마무리 확인" …), 묶음(상시 감시 6 · 웹 서비스 4 · 예약·자동 실행 6), 태그(상시·예약·자동), 주기 문구를 붙였다.
  여러 유닛이 한 라벨이면 `units` 로 센다. 실행 기록을 찾지 못한 예약 작업은 "기록 없음 · 확인 필요" 로 남겼다.
- 상태: 상시 서비스는 가동 중, 예약은 실패 0 이면 정상 · 1 이상이면 "실패 있음" · 기록이 없으면 "기록 없음".

### 2.5 맨 위 합계

맨 위 노드의 수는 `레인 + 에이전트 세션 + 서비스 종류` 다(원 보드 1,999 = 177 + 1,806 + 16). 상주 창은 더하지 않는다.

## 3. 개인 정보 빼는 규칙

화면·HTML·PNG·증거 파일 어디에도 넣지 않는 것: 대화 내용, 메신저 방 이름, 사람 이름, 전화번호, 토큰·키·비밀번호,
홈 경로, 호스트 이름, **레인 제목과 레인 키**(제목에 사람 이름, 키에 호스트 이름 조각이 있었다), 유닛 설명문.

- 세션은 **종류와 일반 라벨**로만 부른다("카톡 감시", "뉴스 정리"). 라벨을 못 정하면 "세션 N".
- 수집 단계에서 지운다: 에이전트 세션 목록은 받자마자 사용자 문장 칸을 버리고, 레인은 분류가 끝나면 키·제목 없이
  `{분야, 주제, 상태, 시작, 끝, 걸린 시간, carried}` 만 남긴 정규화 데이터(`data.json`, 임시 폴더)를 만든다. 생성기는 이 파일만 읽는다.
- 검사(QA C2)는 금칙어 목록을 **커널 안에서만** 만들고 출력하지 않는다: 호스트 이름, 사용자 이름, 홈 경로 접두어, 알려진 사람·방 이름,
  메신저 방 상태 파일의 이름들, **모든 레인 제목과 8자 이상 레인 키**, 비밀 설정 파일의 긴 값. 여기에 전화·이메일·토큰·
  홈 경로·IP 정규식 5종. 원 보드는 444개 단어 + 5개 패턴으로 텍스트 파일 적중 0건이었다.
- PNG 는 바이트를 정규식으로 훑으면 압축된 픽셀 안에서 우연히 맞는다. 그래서 PNG 는 **청크 구조**를 읽어 `IHDR`·`IDAT`·`IEND`
  (와 색 정보 청크)만 있고 글자 청크가 없는지로 판정했다. **[추정]** 픽셀 속 글자는 기계로 읽지 않았으므로(OCR 없음),
  화면 문구 자체는 위의 HTML 검사와 사람이 캡처를 보는 것으로 막는다.

## 4. 화면 구조

자체 완결 HTML 한 장: `<script>`·`<link>`·외부 URL·`@import`·`url(` 이 0개이고, 아이콘은 인라인 SVG 경로, 글꼴은 시스템
글꼴 목록(`Pretendard, Noto Sans CJK KR, Noto Sans KR, Apple SD Gothic Neo, Malgun Gothic, system-ui`)이다.
`word-break:keep-all` 로 한국어를 낱말 단위로 줄바꿈한다.

위에서 아래로:

1. **머리**: 작은 영문 머리말(`SESSION BOARD · 지난 7일`), 제목 "이번 주 에이전트가 한 일", 기간 줄
   `10월 9일(금) 00:00 ~ 10월 16일(금) 16:29 · 한국 시간 · 이 컴퓨터 한 대 기준`, 오른쪽에 상태 범례(점 + 글자 7개).
2. **맨 위 요약 노드**(`section.overview`): 알약 모양 허브 "지난 7일 · 모든 세션 / N개를 세 갈래로 정리" 에서 연결선이
   세 기둥 카드로 갈라진다 — 작업 레인(큰 숫자 + 상태별 건수), 에이전트 세션(큰 숫자 + 누적 시간 · 응답 수 · 상주 창),
   감시·서비스(종 수 + 상시 가동 · 예약 실행 횟수).
3. **일별 막대**(`section.trend`): 왼쪽 설명(가장 바빴던 날, 막대에서 뺀 carried 수) + "새 작업 레인(건)" 막대 8개 +
   "새 에이전트 세션(개)" 막대 8개. 막대 높이는 `값 / 최댓값`(최소 3%), 막대 위에 값, 아래에 `9일 금` 같은 날짜,
   가장 바쁜 날은 굵게. 날짜는 KST 하루 단위다.
4. **세 갈래**(`section.branch`, 각각 `data-kind`·`data-count`): 갈래마다 알약 허브 노드 → 연결선 → 분야 카드 격자.
   - 작업 레인 갈래: 분야 카드 6장(운영·비서·연구·웹·조사·인프라), 카드 안에 **주제별 멤버 카드**.
   - 에이전트 세션 갈래: 클로드 코드 · 센피 · 상주 작업 창 · 다른 에이전트("없음" 점선 칸) 4장, 카드 안에 **모델별·창 종류별 멤버 카드**.
   - 감시·서비스 갈래: 상시 감시 · 웹 서비스 · 예약·자동 실행 3장, 카드 안에 서비스별 멤버 카드.
   - 분야 카드(`section.dept`, `data-dept`·`data-count`): 색 원 아이콘, 영문 소제목(`OPERATIONS`), 한국어 이름, 요약
     (`77건 · 완료 76 · 확인 대기 1`), 멤버 카드 목록. 카드 배경은 분야 색 12% 를 섞은 위→아래 그라데이션.
   - 멤버 카드: 아이콘, 이름, 오른쪽 건수, 태그 칩(수동·에이전트·상주·상시·예약·자동), **상태 점 + 상태 글자**
     (색만으로 말하지 않는다), 기간 줄(`10월 11일 09:51 → 16일 16:15`, 열려 있으면 `→ 진행 중`), 흐린 보조 줄
     (`걸린 시간 합계 …`, `합계 … · 응답 …회`, `7일간 시작 …회`).
   - 멤버 카드 상태는 묶인 것들 중 **가장 나쁜 것**(미완 > 멈춤 > 실패 있음 > 진행 > 확인 대기 > 가동 중 > 정상 > 완료 > 종료 > 기록 없음).
5. **꼬리말**: 기준 데이터, "대화 내용은 읽지 않음", 걸린 시간·누적 시간 세는 법, 만든 시각.

### 4.2 데스크톱과 휴대폰 폭

- 데스크톱: `.board` 최대 폭 1720px, 패딩 40/32px. 연결선은 CSS 만으로 그린다 — 부모 아래 세로선(`.parent::after`),
  자식 격자 위 가로선(`.kids::before`, 격자 열 수 `--n` 으로 양 끝을 계산), 자식마다 세로선(`.kid::before`).
  분야 격자는 `repeat(var(--n), minmax(0,1fr))`.
- 휴대폰(`@media (max-width:640px)`): 모든 격자가 한 열, 연결선은 **왼쪽 세로 척추**(`.kids::before` 를 세로선으로) +
  자식마다 가로 가지(`.kid::before`), 마지막 자식 아래 척추를 바탕색으로 덮어 끝낸다. 제목 24px, 큰 숫자 32px, 막대 판 한 열.
- 캡처 폭: 데스크톱 **1720px**(원 보드 1720×3916), 휴대폰 **390px**(390×10796). 휴대폰 그림은 매우 길다(8장).

## 5. 만든 절차(원 lane 이 실제로 한 순서)

1. **브리프**: 목표·끝난 상태(`board.html` 자체 완결 · 데스크톱 1600px 이상 · 휴대폰 390px · 개인 정보 0 · `report.json`
   `{"qa_pass": true}` + 항목별 증거)·장면·넘으면 안 되는 선(읽기만, 아무 데도 보내지 않음)을 받았다.
2. **참고 화면**: 다른 연구원이 공유한 조직도식 에이전트 현황 그림 — 어두운 배경, 위에서 아래로 갈라지는 연결선,
   부서 카드 안 에이전트 카드, 상태 점, "예약·수동" 같은 작은 태그. 그 구조를 위 4장 그대로 옮겼다.
3. **스킬**: `coding-agent-sessions`(세션 기록 위치·형식과 찾기 스크립트), `visual-qa`(점검 목록과 캡처), `frontend`
   (참고 이미지를 코드로 옮기는 지침), `bun-1-4`(스크린샷 도구). 별도로 하위 조사 하나가 Apple HIG 에서 정적 어두운
   현황 그림에 맞는 보편 규칙(대비·글자 크기·색만으로 말하지 않기 등)을 뽑았다.
4. **수집**(js 커널, 읽기 전용): 2장의 명령으로 모으고 분류·집계해 정규화 `data.json` 을 임시 폴더에 썼다.
5. **생성**: Bun 스크립트 `gen.mjs <data.json> <board.html>`(약 23KB) 하나가 HTML 문자열을 만든다. 구조는 날짜 포맷터
   (`Intl.DateTimeFormat('ko-KR', {timeZone:'Asia/Seoul'})`), 아이콘 경로 표, 상태 표와 우선순위, 갈래별 집계 함수
   (`laneDept`·`agentDept`·`aoeDept`·`svcDept`), 막대 함수, 렌더 조각(`member`·`dept`·`hub`·`branch`·`pillar`), 인라인 CSS 다.
   모든 글자는 `&<>"` 를 이스케이프한다.
6. **캡처**: 먼저 `Bun.WebView` 로 시도했고, 이어서 Playwright 가 받아 둔 `chrome-headless-shell` 을 `--remote-debugging-port=0
   --no-sandbox --hide-scrollbars` 로 띄워 CDP 로 직접 몰았다. **[추정]** WebView 경로는 이 호스트에서 쓰지 못했다(바로
   다음 단계에서 크롬 실행 파일을 찾았다). 방법: `Emulation.setDeviceMetricsOverride({width, height:900, mobile})` →
   `Page.navigate(file://…)` → load 이벤트와 `document.fonts.ready` → `scrollHeight`·`scrollWidth` 측정 → 높이를
   전체로 바꿔 `Page.captureScreenshot({captureBeyondViewport:true})`. `Network.requestWillBeSent` 를 모아 외부 요청을 센다.
7. **보고 고치기**: 첫 캡처를 구역별로 잘라 눈으로 보고 네 가지를 고쳤다 — ① 휴대폰에서 카드가 오른쪽에서 잘림
   (`scrollWidth` 404 > 390, `.kids` 에 `width:auto`), ② 갈래 위 소제목이 허브 노드와 중복되고 휴대폰에서 두 줄로 감김
   (소제목을 지우고 허브 부제로 옮김), ③ 머리 날짜 순서 `00:00(금)` → `(금) 00:00`, ④ "확인 대기" 색이 완료 초록과 너무
   비슷함(청록 → 보라 `#c084fc`). 고치기 전후 캡처를 `qa/before-*`·`qa/after-*` 로 남겼다.
8. **QA·보고**: 6장의 다섯 검사 → `report.json` → 다시 읽어 확인 → `README.md`.

### 5.1 되살린 생성기·수집기와 다시 만드는 법

원 lane 은 `gen.mjs` 와 `data.json` 을 임시 폴더에 두었고 끝날 때 폴더째 지웠다. lane 의 실행 기록(세션 JSONL)에는 `gen.mjs`
를 쓴 호출 원문과 그 뒤 한 번 고친 편집 5건, 수집·분류·집계 코드가 그대로 남아 있었다. 거기서 되살린 것:

| 파일 | 무엇 |
|---|---|
| [`세션-현황판/gen.mjs`](세션-현황판/gen.mjs) | 원 생성기 원문 + 5장 7단계의 편집 5건을 그대로 적용한 것. 손대지 않았다 |
| [`automation/project_board/session_feed/collect.mjs`](../../automation/project_board/session_feed/collect.mjs) | 원 lane 의 수집·분류·집계 코드(2장)를 한 스크립트로 묶은 것(대시보드 통합 때 이 문서 옆에서 옮기고, 서비스는 손으로 쓴 시각 대신 systemd 에서 읽게 바꿨다 — 7.4). 호스트마다 다른 것(레지스트리 폴더, 레인 분류 규칙, 서비스 표, 리드·프로젝트 창 이름)은 환경변수와 바깥 JSON 파일로 뺐다 — 그 값에는 레인 키·사람 이름이 들어 있으므로 **저장소에 넣지 않는다** |
| [`세션-현황판/sample-data.json`](세션-현황판/sample-data.json) | `gen.mjs` 가 읽는 `data.json` 모양의 **지어낸** 예시(레인 13 · 에이전트 세션 40 · 상주 창 4 · 서비스 6) |

`data.json` 모양: `{w0, now, lanes:[{dept, theme, st, start, end, dur, carried}], agents:[{platform, fam, start, end, dur, calls, live}],
aoe:[{kind, start}], services:[{label, group, tag, units, st, start?, restarts?, runs?, fails?, every?, last?}]}` — 시각은 epoch 밀리초,
`dept` 는 `ops|assistant|research|web|study|infra|etc`, `group` 은 `watch|web|timer`, `kind` 는 `lead|lane|proj`.

```bash
# 지어낸 예시로 화면만 보기
bun docs/guide/세션-현황판/gen.mjs docs/guide/세션-현황판/sample-data.json /tmp/board.html

# 실제 호스트에서(값은 그 호스트의 비공개 파일; 저장소에 넣지 않는다)
SB_LANE_DIRS=<레지스트리 폴더1>:<폴더2> SB_LANE_RULES=<rules.json> SB_SERVICES=<services.json> \
SB_CACHE=<비공개 캐시.json> \
  bun automation/project_board/session_feed/collect.mjs <data.json>
bun docs/guide/세션-현황판/gen.mjs <data.json> <board.html>
```

`rules.json` 은 `[["<레인 키 정규식>", "<분야 id>", "<일반 주제 라벨>"], …]`, `services.json` 은
`[{"label", "group": "watch|web|timer", "tag", "units": ["<사용자 유닛>", …], "every"?}]` 이고 상태·시작 시각·시작 횟수·실행·실패·마지막 실행은
`systemctl --user show` 와 `journalctl --user` 에서 읽는다(유닛 이름은 출력에 나가지 않는다). 아래 비교는 옮기기 전 표 방식으로 한 것이다. `SB_NOW` 로 "지금"을 고정할 수 있다.

**원본과 비교한 결과**(2026-10-16): 원 lane 기록의 분류 규칙·서비스 표를 비공개 임시 파일로 꺼내고 `SB_NOW` 를 원 보드의 만든
시각(16:29 KST)으로 고정해 `collect.mjs` → `gen.mjs` 를 돌렸다. 결과 HTML 은 원본과 **같은 크기(63,496바이트)**이고 CSS·태그와

그 뒤 실제로 바뀐 기록 때문이다 — 원 보드 뒤에도 계속 쓰인 세션 파일의 응답 줄 수(예: 응답 148,335회 → 148,534회,

## 7. 프로젝트 대시보드에 통합할 때

### 7.1 먼저 따를 절차

통합은 화면 작업이므로 소유자의 UI 7단계를 그대로 밟는다:

1. Apple HIG 를 전부 읽고 핵심 요소를 뽑는다.
2. 그 관점으로 대시보드를 살피고, 애플 고유 요소는 빼고 사용자·경험·여정에서 나온 보편 기준으로 이상적 상태를 정한다.
3. 제품과 이상적 상태의 차이를 빠짐없이 적는다.
4. AI slop·프론트엔드 스킬과 참고 문서를 모두 읽고 위반을 적는다.
5. 직접 스크린샷을 찍어 위반을 캡처로 남긴다.
6. 고치고, 고쳐졌음을 확인하는 장치까지 넣어 visual QA 조건을 하나도 빼지 않고 검증한다.
7. PR 마다 전후 캡처를 붙이고 진행을 자주 알린다.

대시보드 문서([프로젝트-대시보드.md](프로젝트-대시보드.md) §4)의 기준 — 데스크톱과 390px 에서 가로 스크롤 없음, 누르는 것
44px 이상, 밝은·어두운 모드 모두 대비 4.5:1 이상, 상태는 색만으로 말하지 않음 — 도 같은 검증에 들어간다. 캡처는 데모 보드로 찍는다.

### 7.2 붙일 자리(지금 코드에서 확인한 것)

- 탭 목록: `automation/project_board/dashboard.py` 의 `TABS`(요약·프로젝트·할 일·일정·근거·보관함)에 `("sessions", "세션")`
  같은 한 줄을 더하고, 탭 아이콘을 `dashboard_theme.py` 의 아이콘 정의에 더한다. 탭 전환 스크립트(`_TABS_JS`)는
  `main>[data-tab]` 과 `nav a[data-tab]` 을 읽고 모르는 주소는 요약으로 돌리므로, 새 화면은
  `<section id="sessions" data-tab="sessions">` 하나면 주소 `#sessions` 로 열린다.
- 렌더: 같은 파일의 다른 화면처럼 `_sessions(…) -> str` 를 만들어 `render_dashboard` 에서 이어 붙인다. 머리는 `_head`,
  카드는 기존 카드 클래스를 쓴다. 대시보드는 **Python 표준 라이브러리로 문자열을 렌더**하므로 Bun `gen.mjs` 를 부르지 않고,
  그 함수 구성(`laneDept`·`agentDept`·`aoeDept`·`svcDept`·`bars`·`member`·`dept`·`branch`)을 Python 으로 옮긴다.
  옮긴 뒤 `sample-data.json` 을 두 렌더러에 넣어 숫자·문구가 같은지 대조하면 옮기면서 생긴 차이를 잡는다.
- 데이터: 대시보드의 `BoardSnapshot` 과 섞지 말고 별도 읽기 전용 수집 결과(2장의 정규화 데이터 모양)를 받는다.
  **[추정]** 대시보드는 노드에서 돌고 레인·에이전트 세션 기록은 작업 호스트에 있으므로, 수집기를 어느 호스트에서 돌리고 결과를
  어떻게 넘길지(파일 하나 · 주기)를 먼저 정해야 한다. 정해지기 전에는 탭이 "아직 비어 있습니다" 칸을 보인다.
- 데모: `automation/project_board/demo.py` 가 지어낸 과제·사람·메일로 보드를 채우듯, 세션 화면도 **지어낸 레인·세션·서비스**
  묶음을 데모에 더한다. 문서·PR 캡처는 데모로만 찍는다.

### 7.3 바꿀 점

- **디자인 토큰**: 원 보드의 색·크기 값을 직접 쓰지 않고 `dashboard_theme.py` 토큰으로 바꾼다. 대시보드는 **밝은 모드가
  기본이고 어두운 모드는 `prefers-color-scheme` 로 덮는 한 블록**이다 — 원 보드는 어두운 모드만 있다. 대응 [추정]:
  `--bg`→`--bg`, `--panel`→`--surface`, `--card`→`--surface-2`, `--line`→`--line`, `--text`→`--text`, `--muted`→`--text-2`,
  `--dim`→`--text-3`; 상태색 완료→`--ok`, 진행→`--accent`, 멈춤·실패 있음→`--warn`, 미완→`--danger`, 종료·기록 없음→`--neutral`.
  "확인 대기"(보라)와 갈래·분야 색은 맞는 토큰이 없어 토큰을 더하거나 줄여야 한다 — 대시보드 규칙상 빨강은 지연, 초록은 완료만 뜻한다.
- **글자 크기와 누르는 크기**: 원 보드의 12~12.5px 보조 글자는 대시보드 기준(데스크톱 본문 15·보조 14·배지 13px, 휴대폰
  본문 17·보조 15px, `--t-*` 토큰)보다 작다. 누를 수 있는 것을 만들면 44px(`--hit`)을 지킨다.
- **폭**: 대시보드 최대 폭은 `--max:1200px` 이고 원 보드는 1720px 에 분야 카드 6장을 한 줄로 놓는다. **[추정]** 1200px 에서는
  6열이 좁으므로 3열로 접거나 분야 카드를 대시보드의 접기(`_fold`) 묶음으로 바꾼다.
- **휴대폰**: 대시보드는 640px 이하에서 탭이 화면 아래 고정 막대가 된다. 원 보드 휴대폰 그림은 390×10796 으로 길어서,
  분야·멤버 카드를 접힌 상태로 시작하는 편이 대시보드의 목록 접기 방식과 맞다 **[추정]**.
- **연결선**: 원 보드의 `color-mix` 연결선과 `--n` 격자 계산은 대시보드 CSS 에 없는 기법이다. 그대로 가져가되 토큰 색으로 바꾸고,
  어두운·밝은 모드 둘 다에서 캡처로 확인한다.
- **개인 정보**: 3장 규칙을 코드로 옮긴다 — 레인 키·제목을 렌더 데이터에 넣지 않는 수집기, 그리고 대시보드의 업무 보안 등급
  테스트처럼 지어낸 이름이 화면에 나오지 않는지 확인하는 단위 테스트. 밖으로 나가는 사본(`digest`)에는 세션 탭을 싣지 않을지 먼저 정한다.

### 7.4 통합한 모양(2026-10-16)

소유자 지시 "같은 주소로 하고 탭만 새로 열고 그리고 UI 스킬 써가지고 다듬어"와 "모바일 환경 고려"로 대시보드의 마지막 탭
「세션」(`#sessions`)이 됐다. 화면과 데이터 경로는 [프로젝트-대시보드.md](프로젝트-대시보드.md) 4장 「세션 탭」이 정본이다.
7.2·7.3 에서 정한 것과 다르게 된 점만 적는다.

- 렌더러는 `gen.mjs` 를 줄마다 옮기지 않고 대시보드 부품으로 다시 짰다(`sessions.py` 읽기, `sessions_view.py` 화면). 같은 숫자는
  `tests/unit/test_project_board_sessions.py` 가 `sample-data.json` 으로 확인한다(갈래·묶음 건수가 원천과 같다).
- 원 보드의 색·크기는 모두 대시보드 토큰으로 바뀌었고 분야별 색·갈래별 색은 버렸다(구분은 아이콘과 이름이 한다). 상태는 다른 탭의
  배지를 그대로 쓰고 「확인 대기」는 색 없는 테두리 배지다. 막대는 세로 막대 대신 날짜·막대(`<meter>`)·값의 가로 줄이다.
- 분야·플랫폼·서비스 묶음은 접힌 카드로 시작한다. 멤버 카드의 「수동·에이전트·상주」 태그는 뜨으로 구분되지 않아 뺐고 서비스의
  「상시·예약·자동」만 남았다.
- 데이터는 작업 컴퓨터가 10분마다 `session_feed/feed.sh` 로 보드 루트 `sessions.json` 에 넣는다. 서비스 표는 이제
  사람이 적는 것이 라벨·묶음·유닛 이름뿐이고 나머지는 그때마다 systemd 에서 읽는다(8장의 「한 번 찍은 스냅숏」은 이것으로 풀렸다).
- 밖으로 나가는 사본(`digest`)에는 싣지 않는다.
- **대기와 막힘**(2026-10-16, 소유자 지적 「왜 멈춤으로 되어 있어?」): 원 보드의 「멈춤」은 기다리며 쉬어 둔 레인과
  정말 멈춘 레인을 가르지 못해 소유자가 정지로 읽었다. 이제 `paused` 는 `wait`(대기, 중립색)이고 카드에 무엇을·언제까지
  기다리는지 한 줄이 붙으며, dori 가 작업 창을 `error`·`waiting`·`question` 으로 표시했거나 그 tmux 세션이 없는 열린 레인만
  `block`(막힘)이다. `idle`(자기 감시를 기다리며 턴을 끝낸 것)은 진행이다. 쉬는 동안 완료를 주장한 레인은 확인 대기다.
  레인 행에는 선택 칸 `why`(80자 이하)·`since`(사유를 적은 시각)·`until`(예정 시각)이 더해졌다. `sample-data.json` 은 예전
  수집기 모양(`hold`)을 일부러 남겨 두 새 렌더러가 그것을 대기로 읽는지 시험하고, `gen.mjs` 는 그대로 돌아간다.

## 8. 남은 한계

- **원 `data.json` 은 되살리지 못했다**: 원 lane 의 임시 폴더째 지워졌다. 같은 시점으로 다시 모은 데이터는 5.1 의 8조각만 다르다.
  생성기는 lane 기록에서 되살렸으나 원 lane 이 저장소 밖에서 한 번 쓰고 버린 코드라 단위 테스트가 없다.
- **응답 수 세는 법의 빈틈**: `grep -c` 는 세션 파일 전체를 세므로 "지금"을 과거로 고정해도 그 뒤 쓰인 줄까지 센다(5.1 의 차이 원인).
- **손으로 만든 두 표**: 레인 분류 정규식과 서비스 16종 목록은 이 호스트에 맞춰 사람이 쓴 것이다. 새 레인 이름·새 서비스가
  생기면 "기타"·누락이 된다. 통합 때는 레인 쪽은 태그나 저장소 같은 일반 칸으로, 서비스 쪽은 유닛 이름 패턴 목록(설정)으로 바꿔야 한다 **[추정]**.
- **한 번 찍은 스냅숏**이다: 수치는 만든 시각(16:29 KST) 기준이고 자동 갱신이 없다.
- **응답 수**는 기록 줄 수라 근사값이다(2.3).
- 예약 작업 1종은 실행 기록을 찾지 못해 "기록 없음"으로 나갔다.
- 화면 검사의 자동 판정은 휴대폰 가로 넘침 하나이고, 나머지는 사람이 캡처를 보고 판단했다. PNG 속 글자는 OCR 로 검사하지 않았다.
- 대표 화면 그림은 이 문서에 붙이지 않았다: 저장소에 추적되는 그림이 없고, 그 그림에는 이 호스트의 작업 분야 이름이 그대로
  보인다. 통합 PR 은 데모 데이터로 찍은 전후 캡처를 PR 본문에 싣는다.
