## 2. 무엇이 다른가

| 항목 | 기관메일 다이제스트 | 표준 승인(캘린더 다이제스트) |
|---|---|---|
| 부모 메시지 | 자체 머리말 `## 📬 …` + 사용법 꼬리말. 🔔 승인 대기 없음 | 표준 안내(대상·사실 🔔 승인 대기·위치·인계·되돌리기). 10/16 은 `owner-ko-v1` 다섯 칸이 그대로 보여 장황 |
| 스레드 이름 | `📬 기관메일 다이제스트 MM-DD HH:MM · N건` — 자체 이름, `KIND_ICONS` 밖 | `🗓️ 캘린더 · 다이제스트 YYYY-MM-DD` — `<아이콘> <종류> · <제목>` 규칙 |
| 스레드 첫 메시지 | 없음(바로 메일 카드) | `## <아이콘> <종류> · <제목>` 큰 제목(v1.38.0) |
| 항목 카드 | `### N. 제목` · 회신 키 · 배지 · 요약 · 사람 · 일정 줄 | `**🔔 캘린더 변경**` · 인용 상세 · `**결정:**` · 참조 · 해시 |
| 형 조작 | 📄 전문, ✍️ 회신 초안, 답장=지시대로 초안. **✅ 는 여기 없음** — 초안마다 **다른 스레드**의 카드에서 ✅/⛔ (두 번 이동) | 카드에서 바로 ✅/⛔ |
| 리마인더 | 다이제스트에는 없음. 회신 초안 카드(별도 스레드)에만 표준 리마인더 | 카드마다 매시간 `승인 리마인더` 평문 4줄(10/16: 카드 2장에 3시간 동안 5통) |
| 완료 표시 | 없음 — 스레드는 영원히 열린 채 | 결과는 카드 아래 답글. 일별 스레드는 남은 카드가 있어 닫지 않고, 다 끝나도 `✅ 완료 ·` 접두어·아카이브가 **없다** |
| 실패 노트 | 다이제스트 실패 = `DIGEST-FAIL stage=… code=…` 한 줄이 cron 통지로(스레드 밖). 일정 위임 실패 = 카드 안 `🗓️ 일정 초안 'calendar-refused'` | 카드 게시 실패 = `owner_notice` 봉투 통지(스레드 밖). 실행 실패 = 카드 아래 `⚠️ … 실행 실패` |
| 승인 해시·파서 | 다이제스트 자체는 승인 대상이 아님. 초안 카드는 메일 게이트 표준 | 캘린더 게이트 표준 |

핵심 차이는 둘이다. **(1) 모양** — 부모·이름·첫 메시지가 표준 규칙을 안 쓴다. **(2) 결정 위치** —
다이제스트에서 시작한 회신은 다른 스레드로 가서 ✅ 해야 하고, 같은 아침의 일정 카드도 또 다른
스레드에 있다. 형이 하루 아침에 보는 스레드가 `📬 다이제스트` + `🗓️ 캘린더 다이제스트` +
초안마다 `↩️ 메일 회신 · …` 여러 개로 갈라진다.

## 3. 통합안

두 안 모두 지키는 것: 📄 전문 · ✍️ 회신 초안 · 답장=지시대로 초안 · 회신 키 · 🔴🔵 배지와
`↩️ 회신 필요`/`📤 회신함` · 일정 줄의 승인 카드 링크. 승인 카드의 렌더 판본·`action_hash`·
리액션 파서·`resolve_reaction`·워처는 **바꾸지 않는다**(카드가 어느 채널에 서는지만 레코드의
`channel_id`/`approval_thread_id` 로 달라진다 — 「단일 게이트 절차 재사용」). 메일은 여전히
카드 ✅ 뒤 `watch` 만 보낸다(자동 발송 없음).

### 안 A — 모양만 표준으로 (작음)

다이제스트는 "읽는 스레드"로 두고 겉모양만 표준 규칙에 맞춘다. 결정은 지금처럼 초안별 스레드에서 한다.

```
#agent-chat
┌ ## 📬 메일 · 다이제스트 10-16 08:00 · 19건
│ 📰 정기 보고 · 신규 19건 (회신 필요 3 · 일정 1 · 예산 1)
│ 결정할 것은 이 스레드에 없습니다 — 메일 카드의 📄 전문 · ✍️ 회신 초안 · 답장=지시대로 초안
│ 초안은 「↩️ 메일 회신 · <제목>」 승인 스레드로 올라가고, 카드 아래에 그 링크가 붙습니다
└ 스레드: 📬 메일 · 다이제스트 10-16 08:00 · 19건
    ## 📬 메일 · 다이제스트 10-16 08:00 · 19건
    ### 16. (긴급) ○○ 검토 회의 참석 요청 …      (카드 내용·📄✍️ 그대로)
    …
  다음 날 08:00 새 다이제스트가 열리면 → 어제 스레드 이름 앞에 「✅ 완료 · 」 + 아카이브
```

- 바뀌는 코드: `triage_digest.render_digest_parts`(머리말), `thread_name`, `triage_confirm.digest_thread`
  (공용 `thread_title` 로 큰 제목 게시), `run_digest` 끝에 전날 스레드 종결(`origin_notice.close_thread`).
  `KIND_ICONS` 가 아니라 결과 스레드 표(`origin_notice._THREAD_ICONS` 의 「메일」=✉️)와 겹치지
  않게 📬 를 정기 보고용으로 등록한다.
- 위험: 낮음. 머리말 문구를 고정하는 시험(`tests/unit/test_mail_digest.py`, FS3 고정 —
  새 사례는 별도 파일)과 머리말에 ✅ 가 들어가면 안 되는 가드(`chat_approval_guard`,
  `test_mail_digest_footer.py`)를 지킨다 — 그래서 위 모형의 부모에는 ✅ 글자가 없다.
- 한계: 형 조작은 그대로 두 번 이동이다. "같은 모양"은 되지만 "같은 조작"은 아니다.

### 안 B — 하루 한 승인 스레드로 (권장)

다이제스트 스레드를 캘린더 다이제스트와 같은 **일별 표준 승인 스레드**로 만든다. 그날 아침의
메일 카드, ✍️/답장으로 만든 회신 초안 카드, 그 메일에서 나온 일정 카드가 **한 스레드**에 서고
형은 그 안에서 ✅/⛔ 한다.

```
#agent-chat
┌ ## 📬 메일 · 다이제스트 10-16 08:00 · 19건
│ 🔔 승인 대기 0건 — 회신 초안·일정 카드가 생기면 이 스레드에서 ✅ 실행 / ⛔ 취소
│ 신규 19건 (회신 필요 3 · 일정 1 · 예산 1) · 📄 전문 · ✍️ 회신 초안 · 답장=지시대로 초안
└ 스레드: 📬 메일 · 다이제스트 10-16 08:00 · 19건
    ## 📬 메일 · 다이제스트 10-16 08:00 · 19건
    ### 16. (긴급) ○○ 검토 회의 참석 요청 …            [📄] [✍️]
      🗓️ 일정 → 아래 카드
      └ (답글) **🔔 캘린더 변경** … **결정:** ✅ 실행 / ⛔ 취소        [✅] [⛔]
    ### 10. ○○ 원격회의 의견 요청 …                      [📄] [✍️]
      ↩️ 회신 필요
      └ (형이 ✍️) 회신 초안 미리보기 + **메일 회신 승인 카드**        [✅] [⛔]
           └ (✅ 뒤 답글) ✅ 발송 완료 · 수신자 …
    승인 리마인더 → 결정 안 된 카드에만, 표준 리마인더 그대로
  남은 결정 0건 + 다음 다이제스트가 열림 → 이름 앞 「✅ 완료 · 」 + 아카이브
  (결정 안 된 카드가 남아 있으면 열어 두고 이름 앞 「🔔 」 유지)
```

- 형 장면: 아침에 스레드 하나만 연다. 읽고(📄), 초안을 시키고(✍️/답장), 같은 자리에서 ✅/⛔.
  `↩️ 메일 회신 · …` 별도 스레드와 `🗓️ 캘린더 · 다이제스트` 스레드는 다이제스트 건에 대해서는
  생기지 않는다(다이제스트 밖에서 시킨 회신·일정은 지금처럼 요청별 스레드).
- 바뀌는 코드:
  - 다이제스트 스레드 바인딩 저장: `calendar_digest.daily_binding` 과 같은 방식(게시일 lease +
    `daily-threads/<날짜>.json` 저장 바인딩 재사용)을 메일 쪽에 두고, 다이제스트 머리말을 표준
    `resolve_new_binding(MAIL_REPLY, request=RequestThread(title="다이제스트 …"))` 안내로 연다.
    Discord 는 스레드 안에서 스레드를 못 여므로, 카드 메시지를 앵커로 쓰는 지금 경로
    (`agent_chat_request_thread`)가 아니라 **저장된 스레드 바인딩을 재사용**하는 길이 필요하다.
  - 회신 초안: `digest_reaction_actions._write_draft`·답장 경로(`triage_cli draft` 가 다이제스트
    카드 출처를 알 때)가 그 바인딩으로 카드를 게시하고, 메일 카드에 답글(reply)로 단다.
    결과 통지는 캘린더 `DigestReply` 처럼 자기 카드 아래 답글, 스레드는 항목별로 닫지 않는다.
  - 일정 카드: `calendar_digest` 가 그날 메일 다이제스트 바인딩을 쓰게 한다(교차 스킬 —
    메일이 캘린더 CLI 에 `--digest-thread` 를 넘기는 식).
  - 종결: 다음 다이제스트 때 전날 스레드의 미결 카드 수를 세어 0 이면 `✅ 완료 ·` + 아카이브.
- 위험: 중간. ① 승인 카드의 게시 위치가 바뀐다 — 표면은 같은 `AGENT_CHAT_THREAD` 라 정책
  버전은 그대로지만 conformance(`test_request_thread_adoption_conformance`,
  `test_approval_lifecycle_conformance`)와 레코드 `approval_thread_id` 를 같이 맞춰야 한다.
  ② 메일·캘린더 두 스킬이 한 바인딩을 공유 — lease 로 경합을 막는다. ③ 이미 떠 있는 옛 초안
  카드는 저장된 `channel_id` 그대로라 영향 없음(새 다이제스트부터 적용). ④ 한 스레드가 길어진다
  (19건 + 카드) — 메일 카드 아래 답글로 달아 어느 메일의 결정인지 보이게 한다.
- 함께 고칠 것(두 안 공통으로 넣을 수 있음): 리마인더를 평문 4줄에서 큰 제목 규칙에 맞춘 한
  줄(`⏰ 승인 대기 1시간 · <카드 링크>`)로, 같은 스레드에 같은 시각 여러 카드면 한 통으로.
  부모 안내가 `owner-ko-v1` 다섯 칸으로 나오는 것은 `owner-ko-v2` 로.

## 4. 추천

**B.** 형이 바란 장면이 "같은 모양 + 같은 조작"이고, A 는 모양만 맞춘다. A 를 먼저 하고 B 로
넘어가면 머리말·이름을 두 번 바꾸게 되므로 처음부터 B 를 권한다. 일정이 빠듯하면 A 로 시작해도
B 의 머리말·이름 규칙과 같게 만들어 두 번째 변경을 줄인다.
