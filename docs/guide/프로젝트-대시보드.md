# 프로젝트 대시보드 (v2) — 설계·설정·운영

v1(기관 메일 수집·원본 보관·중복/실패 이력)은 메일 스킬의 mailon 동기화와 첨부 아카이브가 이미 한다.
이 문서는 그 위에 얹은 v2 — 분석 → 담당자 검토·확정 → 승인된 프로젝트 데이터 → 웹 대시보드 → 실행 기록 — 의
규약을 단독으로 소유한다. 사용 시나리오는 [소개](../기능소개/프로젝트-대시보드-v2.md).

## 1. 상자 → 모듈 (`automation/project_board/`)

| 단계 | 모듈 | 불변식 |
|---|---|---|
| 입력(v1 결과) | `sources.py` | MailOn `state.db`·저장 markdown·첨부 파일을 **읽기만** 한다. 경로 해석은 메일 래퍼와 같다(`MAIL_WRAPPER_REPO`·`MAIL_WRAPPER_DB`, 기본 `~/.hermes/mailon-runtime/current`). 회의록은 `meeting_minutes.finalized_view` 로 부록 위만 읽는다(「산출물 출처 규칙」) |
| 분석 | `llm.py`·`analysis.py`·`prompts/project-analysis-v1.md` | 제공자 인터페이스 하나. 기본 `hermes` = `automation.codex_llm`(계정 주 모델·폴백, 코드에 모델 이름 없음). `openai-compatible` 은 설정으로만 고른다. 답은 엄격 파싱 — JSON 아니면·날짜 아니면 실패(추측 금지), `relevant:false` 면 제안 없음 |
| 검토·확정 | `proposals.py`·`proposal_gate.py`·`proposal_render.py`·`cli revise` | 제안 하나 = 카드 하나. `action_hash` = 정규화 제안 JSON 의 sha256. 수정은 같은 key 의 새 판 → 공용 lifecycle 이 미결 옛 카드를 지우고 같은 스레드에 새 카드. ✅/⛔ 된 제안은 고치지 않는다 |
| 승인된 항목만 반영 | `proposal_watch.py`·cron `project-board-watch`(2분) | 소유자(봇 아님) 리액션만, ⛔ 우선. 반영 직전 동결 파일을 다시 해시해 레코드와 대조 |
| 승인 데이터 | `board_store.py`(SQLite `~/.hermes/project-board/board.db`, 0600) | 제안 id 로 멱등. 진행 기록은 상태·진척만 바꾸고 할 일을 만들지 않는다 |
| 대시보드 | `dashboard.py`·`server.py`·사용자 유닛 `autophagy-project-board` | 자체 완결 HTML(외부 폰트·CDN 없음). 서버는 루프백 전용(비루프백 bind 거부)·토큰 필수·체크 POST 는 토큰 2중+같은 Origin |
| 실행 → 기록 | `cli progress`·대시보드 체크 | 기록마다 이벤트 원장 한 줄, 대시보드 파일 재생성 |
| 외부 메일 | `cli digest --request-mail` | 메일 스킬 `compose --attachment` 의 **표준 메일 승인 카드**로만 나간다. 이 패키지는 메일을 보내지 않는다 |

## 2. 설정 (`~/.hermes/project-board/config.json`, 없어도 됨)

```json
{
  "llm": {"provider": "hermes"},
  "analyze": {"enabled": false, "max_per_tick": 5},
  "dashboard": {"port": 8810},
  "digest": {"to": ["<수신 주소>"], "subject": "프로젝트 현황 일일 요약"}
}
```

- 로컬 LLM 으로 바꾸기: `"llm": {"provider": "openai-compatible", "base_url": "http://127.0.0.1:8000/v1",
  "model": "<서버의 모델 id>", "api_key_env": "<키가 필요하면 환경변수 이름>"}`. 모델 id·주소는 이 파일에만 둔다.
  확인: `python3 -m automation.project_board status` 의 `MODEL` 줄.
- `analyze.enabled` 기본 false — 릴리스만으로는 카드가 올라가지 않는다. 켜면 첫 틱은 워터마크를 "지금"으로
  잡기만 하고(과거 메일함 전체를 제안하지 않는다) 그 뒤 새 메일만 본다. 틱당 상한 `max_per_tick`.
- 상태 경로 덮어쓰기: `PROJECT_BOARD_ROOT`, `PROJECT_BOARD_CONFIG`, 회의록 폴더 `PROJECT_BOARD_MEETING_DIR`.
- 과제 목록(카탈로그): `"projects": [{"name": "<과제 이름>", "aliases": ["<별칭>", …], "note": "<한 줄 설명>"}]`.
  분석은 이 목록에서 **글자 그대로** 하나를 고르고, 맞는 것이 없으면 `미분류` 로 답한다(새 이름을 짓지 않는다).
  실제 과제 이름은 노드 설정 파일에만 둔다 — 코드·저장소에 적지 않는다(「개인화 코드 금지 규칙」).
- 프롬프트 판본: `"analyze": {"prompt": "v2"}`(기본). v2 는 광고·자동 알림·전 직원 일반 공지를 사유와 함께 거르고,
  받는 사람에게 요구된 행동만 할 일로 뽑으며, 대시보드에 이미 열린 할 일과 같은 일은 빼고, 상대 날짜도 계산한다.
  `v1` 은 비교용으로 남는다.

## 3. 명령

```bash
python3 -m automation.project_board analyze --mail <uid>        # 또는 --meeting <회의록.md>; 카드 게시 + APPROVAL-THREAD 줄
python3 -m automation.project_board revise <제안> --set-due 1=2026-10-24 --set-owner 2=담당자 --drop 3 --add '제목|담당|2026-11-01'
python3 -m automation.project_board proposals                  # 제안과 상태
python3 -m automation.project_board progress <todo_id> --status 완료|진행|보류|열림 [--progress N] [--note 메모]
python3 -m automation.project_board build                      # 대시보드 파일 다시 만들기
python3 -m automation.project_board serve                      # 127.0.0.1:<port> (유닛이 상시 실행)
python3 -m automation.project_board digest [--request-mail]    # 날짜별 스냅샷, 메일은 승인 카드로만
python3 -m automation.project_board dryrun --days 28 --limit 120 --out <체크아웃 밖 경로>.jsonl [--prompt v1|v2]
```

## 테일넷에서 열기 (tailnet 전용, 공개 아님)

서버는 노드의 루프백(`127.0.0.1:<port>`)에만 붙는다. 소유자 기기에서 https 로 열려면 **테일스케일 운영자 권한이 있는
호스트**(게이트웨이)에서 `tailscale serve` 를 쓰고, 그 호스트가 SSH 포워드로 노드 루프백에 닿게 한다. Funnel(공개)은 쓰지 않는다.

1. 노드 설정 `~/.hermes/project-board/config.json` 에 게이트웨이 주소와 허용 로그인을 적는다(값은 설치별, 저장소에 적지 않는다):
   ```json
   {"dashboard": {"tailnet": {"origins": ["https://<게이트웨이>.<tailnet>.ts.net:<port>"], "logins": ["<소유자 로그인>"]}}}
   ```
   서버는 1시간마다 다시 뜨므로(`RuntimeMaxSec`) 그 안에 반영된다. 즉시 반영하려면 `systemctl --user restart autophagy-project-board`.
2. 게이트웨이에서 노드 루프백으로 가는 상시 포워드(사용자 유닛, `Restart=always`, 사용자 linger 켜기):
   `ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -L 127.0.0.1:<로컬포트>:127.0.0.1:<port> <노드>`
3. 게이트웨이에서 `tailscale serve --bg --https=<port> http://127.0.0.1:<로컬포트>` — `tailscale serve status` 에 `(tailnet only)` 로 보여야 한다. serve 설정은 tailscaled 가 저장해 재부팅 뒤에도 유지된다.
4. 소유자 기기 브라우저에서 처음 한 번 `https://<게이트웨이>.<tailnet>.ts.net:<port>/?t=<토큰>` (토큰은 노드 `~/.hermes/project-board/serve.token`). 이후에는 쿠키로 열린다.

규칙: 테일넷 이름으로 들어온 요청이나 `Tailscale-User-Login` 헤더가 붙은 요청은 그 로그인이 `logins` 에 있어야 하고(아니면 403),
**토큰도 그대로 필요하다**. `tailscale serve` 는 그 헤더를 호출자의 실제 신원으로 덮어쓰지만, 노드·게이트웨이의 다른 로컬
프로세스는 루프백에 직접 헤더를 위조해 보낼 수 있으므로 헤더만으로는 비밀이 될 수 없다. 테일넷 설정이 없으면 신원 헤더가
붙은 요청은 모두 거부된다. TODO 체크(POST)는 설정된 테일넷 출처의 `Origin` 도 받는다.

`dryrun` 은 운영 전 분류 점검용이다 — 최근 받은 메일을 그대로 분석해 결과를 비공개 JSONL(0600) 한 파일에만 쓰고,
제안·카드·프로젝트 데이터·대시보드는 하나도 만들지 않으며 메일함은 읽기만 한다. git 체크아웃 안 경로는 거부한다.

MailOn 런타임의 `data/` 는 배포본에서 공유 상태 디렉터리(`mailon-runtime/state/data`)로 가는 링크다. 원문·첨부
경로는 런타임 루트 또는 그 `data/` 실경로 안일 때만 읽고, 그 밖으로 풀리는 경로는 거부한다.

종료 코드: 0 완료, 2 입력 오류, 3 카드 게시 거부, 4 모델·원천 일시 불가(재시도).
