# 소비 노드 첫 전량 반영에서 드러난 공백 (2026-10-19, v2.4.0)

릴리스를 받아 쓰기만 하던 노드(설치 뒤 `deploy_all.sh` 가 한 번도 돌지 않은 노드)에서 운영자 계정을
릴리스 호스트로 삼아 정상 경로(릴리스 카드 ✅ → `deploy_all.sh --apply`)로 첫 전량 반영을 했을 때
막힌 곳들이다. 사이토플라즘 코드·서명·승인 검사는 고치지 않고 우회 없이 진행했고, 아래 「노드에서 한 일」은
그때 쓴 비파괴 조치다. 이 PR 은 1·5·6·7·8번을 코드로 고치고(각 절의 「수정」), 2·3·4번은 재현·원인·제안만 적는다.

자리표시: `<node>` 노드 이름, `<operator>` 운영자 계정, `<notice-channel>` 알림 봇 채널, `<approvals-channel>` 옛 승인 채널.

## 1. 게이트웨이 정지 때 cron 목록 전체가 판독 불가 (이 PR 에서 수정)

- **재현**: hermes-gateways=stopped 스위치로 agent·peer 게이트웨이를 멈춘 노드에서 `deploy_all_probe.py --format report`.
  모든 cron 행이 `ARTIFACT-UNKNOWN … unreadable-listing`, 배포기는 `CRON-TIMER-BLOCK: hermes cron list --all failed or was unreadable`.
- **원인**: 2026-10 Hermes 의 `hermes_cli/cron.py::_warn_if_gateway_not_running` 은 옛 `  ⚠  Gateway is not running …` 대신
  `  ⚠  Scheduler is not ready for profile '<profile>': …` 2칸 줄을 찍는다. `automation/deploy_all_cron_listing.py` 와
  `automation/deploy_cron.sh::_converge_cron_jobs` 는 옛 문구만 건너뛰어 새 줄을 「다른 2칸 줄」로 보고 목록 전체를 버린다.
- **영향**: 정지 전에 systemd 타이머로 옮겨지지 않은 잡은 옮길 수 없고(게이트웨이가 없으니 돌지도 않는다), 판정은 영영 깨끗해지지 않아 영수증이 써지지 않는다(→ 8번).
- **수정**: 두 해석기에 같은 접두어를 하나 더한다. 안내 줄(5칸 이상) 모양은 같아 다른 변경은 없다.
  회귀 `tests/unit/test_cron_listing_scheduler_warning.py`(새 경고·모르는 2칸 줄·옛 경고, 두 해석기 모두).
- **수정(게이트웨이를 켜지 않는 수렴)**: CLI 목록이 실패하거나 여전히 판독 불가일 때, 계정의 `gateway-stopped-by-release` 가
  정확한 `stopped` 이면 `cron_timer` 가 러너와 같은 `~/.hermes/cron/jobs.json` 을 새로 읽어 잡 상태를 판정한다(pause 는 계속 Hermes CLI).
  표식이 없으면 예전처럼 rc 4. 규약 `docs/guide/cron-timer-offline.md`, 회귀 `tests/unit/test_cron_timer_gateway_stopped.py`.

## 2. memory-choices 폴더의 setgid 가 빠져 영구 거부

- **재현**: 설치기 기본 계정 구성에서 `automation/memory_relocate/deploy.sh` → `MEMORY-CHOICES-PROVISION-REFUSED type=ChoiceError`(`handoff_permissions`).
- **원인**: `choice_accounts.provision_shared` 가 ops 로 `chmod(0o3770)` 하지만 `bootstrap-accounts.sh::provision_group` 은 ops 를 서비스 그룹에 넣지 않는다.
  그룹 밖 소유자의 chmod 는 커널이 S_ISGID 를 지워 폴더가 1770 으로 남고, 폴더가 이미 있으면 다시 고치지 않는다.
- **노드에서 한 일**: 빈 폴더를 ops 로 지우고 umask 0 에서 `os.mkdir(path, 0o1770)` — 부모의 setgid 를 물려받아 3770 이 된다.
- **제안**: `provision_shared` 가 chmod 대신 setgid 부모 아래 `mkdir` 상속에 기대거나, 모양이 틀린 빈 폴더는 다시 만든다.

## 3. 오래된 노드의 interop 닭과 달걀

- **재현**: 9월 설치 노드에서 `automation/interop/deploy.sh` → `INTEROP-DEPLOY-BLOCK: the gate code on agent does not read the new rule file`.
- **원인**: (b) 단계는 `~/.hermes/autophagy-import` 가 없으면 옛 `~/.hermes/interop_runtime` 으로 새 규칙을 읽어 보는데, 옛 런타임엔 `external_effect_gate` 가 없다. 런타임 교체는 같은 배포기의 뒤 단계(g2)다.
- **노드에서 한 일**: 릴리스의 `automation/interop/pin_import_root.sh` 를 agent·peer 로 실행(게이트웨이 ExecStartPre 와 같은 동작).
- **제안**: (b) 가 `autophagy-import` 부재 시 릴리스 트리(pin 과 같은 해석)로 검증하거나, 배포기 첫 단계에서 pin 을 실행한다.

## 4. 소비 노드에서 provenance 기준이 origin/main 고정

- **재현**: 서명 태그로 체크아웃한 뒤 main 이 태그보다 앞선 상태에서 `deploy_all.sh --apply` → 모든 배포기 `DEPLOY-BLOCK … differs from origin/main`.
- **노드에서 한 일**: 문서화된 `DEPLOY_PROVENANCE_REF=<tag>` 로 실행(검사는 그대로 켜짐).
- **제안**: 소비 노드 절차 문서에 이 변수를 적거나, 체크아웃이 서명 태그와 같으면 그 태그를 기본 기준으로 쓴다.

## 5. 소유자가 끈 정기 작업을 배포기가 다시 켬

- **재현**: 소유자가 타이머를 끈 `budget-watch`·`mail-attachment-drive-watch`·`daily-cost-report` 가 있는 노드에서 `--apply` 를 돌리면 해당 배포기가 타이머를 다시 켜고, 판정기는 끈 동안 계속 그 배포기를 할 일로 낸다.
- **원인**: `cron_timer` 의 released-off 는 메모리 타이머(`legacy_services.memory_timer_off`)만 인정한다.
- **수정**: 릴리스 호스트 스위치 `~/.hermes/release-flags/cron-timers-off`(정렬·중복 없는 잡 이름, 한 줄에 하나, 끝 줄도 LF)를 둔다.
  이름마다 `cron-timer:<이름>:off` 표면이 릴리스 승인 해시와 카드에 묶이고, `deploy_all` 이 같은 HEAD 승인을 확인한 뒤 타이머를 끄고
  다시 읽어 노드 표식 `~/.hermes/cron-timers/owner-off.mode` 를 쓴다. `converge` 는 그 잡을 다시 켜지 않고(released-off), `check`·doctor·판정기도
  끈 상태를 정상으로 본다. 파일 삭제+재배포로 되돌린다. 소개 `docs/기능소개/정기-작업-소유자-정지.md`,
  회귀 `tests/unit/test_cron_timer_owner_off*.py`. 일일 지출 보고(`daily-cost-report`)는 상류에서 은퇴해 해당 없다.

## 6. 릴리스 카드는 알림 봇 채널로 가는데 peer attestation 은 옛 핀 채널로 묶임

- **재현**: notice-bot·yoodori-channel 을 켠 뒤 새 릴리스 카드는 설계대로 `<notice-channel>` 에 올라간다(`skill_gate_surface.pinned_channel_id`, 「release and supply-chain approval cards follow the sender-bot channel」).
  그 카드로 `deploy-skill.sh <skill> --release-approval` → `RELEASE-AUTHORIZE: peer attestation absent or expired` 반복, MOUNT 없음.
- **원인**: `deploy-skill.sh` 945행이 attestation 채널을 agent interop config 의 `deploy_approvals_channel_id`(`<approvals-channel>`)에서 읽는다. 기대값은 레코드의 채널(`<notice-channel>`)이라 서명된 attestation 이 맞지 않는다.
- **노드에서 한 일**(소유자 승인): agent interop config 의 `deploy_approvals_channel_id` 만 `<notice-channel>` 로 바꿈(백업 보존).
- **수정**: `--release-approval` 경로는 부모 채널 고정값과 상관없이 `pending/release.json` 의 `channel_id`(릴리스 카드 스레드)로
  최초 증명과 두 갱신을 서명한다. 레코드에 채널이 없으면 peer 호출 전에 rc 4 로 거부한다. 일반 스킬 배포는 고정값 그대로.
  회귀 `tests/unit/test_deploy_skill_release_approval_channel.py`. 노드에서 바꾼 `deploy_approvals_channel_id` 는 원래 값으로 되돌려도 된다.

## 7. 설치된 적 없는 옛 서비스를 끄지 못함

- **재현**: report-hub 를 설치한 적 없는 노드에서 `report-hub-off` 스위치 → `automation/legacy_services/deploy.sh` rc 5(메시지 없음).
- **원인**: `legacy_services._install` 이 없는 유닛에 `systemctl --user stop` → rc 5 를 실패로 본다.
- **수정**: off 모드에서 `systemctl --user show -p LoadState --value` 가 정확히 `not-found` 인(설치된 적 없는) 보기 유닛은
  이미 꺼진 것으로 보고 건너뛴다. 그 밖의 답은 예전처럼 stop·is-active 재확인을 거치고, rc 5 가 나면
  `LEGACY-SERVICE-FAILED unit=<유닛> step=<단계>` 한 줄을 남긴다. 회귀 `tests/unit/test_legacy_services_missing_unit.py`.

## 8. 영수증이 없으면 다음 릴리스가 게이트웨이를 다시 켬

- **재현**: 1·5·7 때문에 판정이 깨끗하지 않아 `deploy-all/receipt.json` 이 없는 노드에서 다음 서명 릴리스가 리컨실러로 들어오면.
- **원인**: `deploy_reconcile_cli.run_release_update` 가 `hermes_gateways.stopped_in_receipt()` 를 읽는데 영수증이 없으면 False(첫 배포 전 설치로 취급) →
  `release_rollback` 이 root 도우미 `gateway-pair restart` 로 두 게이트웨이를 재시동한다. 이 경로는 계정의 정지 표식(`~/.hermes/gateway-stopped-by-release`)을 보지 않는다.
- **영향**: 소유자의 게이트웨이 정지 스위치가 새 릴리스마다 조용히 풀린다.
- **노드에서 한 일**: 새 판을 감시해 같은 정상 경로로 카드를 올리고 ✅ 뒤 `--apply` 로 다시 정지한다.
- **수정**: 리컨실러(ops, `ProtectHome=tmpfs`)는 계정 홈의 표식을 읽을 수 없으므로, `deploy_all.sh --apply` 가 정지 모드에서
  유닛을 바꾸기 전에 ops 소유 `<private_root>/gateway-stopped-by-release`(정확한 `stopped`)를 함께 쓰고, 실행 모드의 깨끗한
  판정으로 영수증을 쓸 때만 지운다. 영수증 파일이 없을 때만 이 표식을 읽어 재시동을 건너뛴다(영수증이 있으면 영수증 우선,
  잘못된 바이트는 거부). 새 sudo 권한 없음. 이 수정 전에 정지한 노드는 다음 `--apply` 까지 표식이 없어 예전처럼 재시동된다.
  회귀 `tests/unit/test_hermes_gateways_marker_fallback.py`.
