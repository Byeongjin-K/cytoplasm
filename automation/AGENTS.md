# automation/ — 오케스트레이션·게이트·워처·배치 코어

에이전트 실시간 로직 밖의 모든 자동화. 순수 로직은 stdlib 전용, 외부효과는 승인 게이트 경유.
Q231의 예외는 `auto_write`의 릴리스 승인된 Plaud 자동 쓰기뿐이다. 아래 Plaud의 건별 카드 설명은
자동 모드가 꺼진 기본 경로이며, 켜면 동결 SHA를 확인해 같은 writer로 쓰고 공용 일일 요약에 남긴다.
`auto_write.record(kind, Entry)`·`summarize(now)`·`release_kinds(home)`는 종류별로 공유한다.
Q233의 다른 종류도 같은 원장·요약을 쓴다(`calendar`·`todo`·`obsidian`·`drive-save`·`project-board`, 종류마다 스위치 하나).
두 번째 종류 `yoodori` 는 유돌 게이트의 형 명령 잡(위키·문서·특허·전사·회의록)이며, `yoodori_gate/yoodori_jobs.py` 가
근거 메시지가 형 본인의 24시간 안 글인지 확인한 뒤에만 돌고 성공한 쓰기를 그 링크와 함께 원장에 남긴다([소개](../docs/기능소개/유돌-형-명령-통로.md)).
대부분 서브패키지는 `python3 -m automation.<pkg>` 또는 `<pkg>/*_cli.py`로 실행.

기관메일 HTML 회신은 `mail_html_reply`의 기본 꺼짐 릴리스 스위치다. 호스트
`release-flags/mail-html-reply`의 정확한 `on`을 같은 HEAD 승인 표면에 묶고,
`mail_html_reply.prepare_deploy`가 설정·활성 HEAD·승인을 확인한 뒤
`mail_html_reply/deploy.sh`가 선언된 `push_file`로 agent 표식을 배치한다.
셸 설정 eval·간접 실행 예외를 추가하지 않고 기존 provenance 닫힌 문법을 지킨다.
삭제+다음 릴리스는 평문 복귀이며, 꺼짐 중 시험은 형 기관주소 전용 초안만 허용한다.
[소개](../docs/기능소개/기관메일-회신-서식-유지.md).

Q4 `hermes-memory-off`는 릴리스 승인에 묶인 가역 스위치다. `legacy_services`가
기존 relocation pending 판독과 워처 잠금 아래 미결이면 두 타이머 모두 무변경으로
거부하고, 없을 때 agent curator·relocate 타이머만 disable·stop한다.
파일 삭제+재배포로 복구하며 USER.md·MEMORY.md·백업·recall은 보존한다.
기억 저장은 유돌 omo(소유자 선호·규칙은 `system/human.md`), 긴 기록은
`obsidian-request`이며 옛 기억 라우팅 패키지는 은퇴했다.

P5 제거는 `peer_retired` 승인 표면과 배포된 계정 표식으로 선택한다. `p5_remove`는
계정별 백업을 검증한 다음 유산·일시정지 잡만 지운다. `deploy_all`은 그 모드에서 peer와
Hermes 전용 선언을 수렴 대상에서 제외하고, 공급망은 owner 승인·리뷰를 유지한 채 peer
증명 단계만 생략한다. root 계정 삭제·sudoers 변경은 실행하지 않는다([소개](../docs/기능소개/p5-제거.md)).

- `selfskill_root_probe.sh` — `healthcheck.sh`가 배선하는 자가 스킬 루트 토폴로지 프로브(읽기 전용): 1차 루트가 mountpoint가 아니고 계정 소유 0700인지, config에 `external_dirs` 항목과 `guard_agent_created`가 있는지 대조하고, 어긋나면 재실행·롤백 경로를 함께 낸다.
- `sudoers.d/`, `*/systemd/` — 배포 대상 권한·유닛 정의.

## 이 디렉터리의 규칙
- **cron 워처는 Discord 리액션만 폴링** (메시지/첨부는 실시간 에이전트 단독 소유 — 경쟁 소비자 금지).
  예외: 행동 없는 수동 인덱서(`rag_ingest`, `report_hub` 폴링, `managed_sync` git remote 폴링, `stt_eval`의 Drive·Obsidian 미러 교정본 수집). `stt_eval`은 비공개 평가 상태만 쓰며 Discord 메시지·첨부를 소비하지 않는다.
  별도 분류: **Discord 수신 없는 내부 큐 executor**(`repair_report_consume_watch`) — Discord 메시지·첨부를 수신하거나 폴링하지 않고, capability-bound 내부 큐를 소비해 카드 readback 뒤 보고를 송신하므로 실시간 에이전트와 경쟁 소비자를 만들지 않는다.
- **no-agent cron**: `~/.env.secrets` 자가 로드 + repo `sys.path` 래퍼 + 자식 subprocess에 자격증명 `env=` 명시 전파.
- 상세 설계 규약: [docs/guide/watcher-cron-설계규약.md](../docs/guide/watcher-cron-설계규약.md).
- **구독자 틱은 둘이 아니라 하나다** — `managed_sync/cron/managed_sync_watch.py`를 Hermes cron(`managed_sync/deploy.sh`)과 systemd 타이머(`managed_sync/systemd/`, 설치기 opt-in)가 함께 쓴다. 놓은 잠금·자격증명 전파·D3 경계를 배포 경로별로 다시 구현하지 말 것. 같은 tick 안에서도 skill tag fetch와 roster ref fetch는 같은 mirror를 쓰되 호출·실패 상태를 분리한다 — roster 브랜치 부재가 skill 배달을 막으면 안 된다.
